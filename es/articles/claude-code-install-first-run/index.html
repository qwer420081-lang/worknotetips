Instalar Claude Code y hacer la primera ejecución: preguntar antes de cambiar código

Comprobamos el comando de instalación de Claude Code y las condiciones de cuenta según el sistema operativo, y comenzamos la primera sesión en una carpeta ficticia de práctica. En lugar de generar código de inmediato, hacemos solo tres preguntas para leer la carpeta y el CSV en modo plan y después cerramos la sesión de forma segura.

01Comprobar la cuenta y el alcance de práctica antes de instalar

Claude Code no debe explicarse suponiendo que su uso es gratuito. La documentación oficial utilizada para este artículo presenta como vías de cuenta una suscripción Claude Pro, Max, Team o Enterprise, créditos prepagados de API en Claude Console o un proveedor de nube compatible. Antes de instalar, hay que comprobar en la documentación oficial y en la pantalla real de la cuenta cuál de estas opciones corresponde. Este artículo no inventa precios ni números de versión concretos.

PreparaciónQué comprobarElección en este artículo

En Windows nativo se recomienda instalar Git for Windows. Si no está instalado, Claude Code puede usar PowerShell como herramienta de shell. El uso de Git se verá en el artículo 6, así que aquí nos centramos solo en el entorno de instalación y la primera sesión.

02Usar el comando oficial de instalación correspondiente al sistema operativo

El comando de instalación nativa recomendado depende del sistema operativo. Antes de copiar los comandos siguientes, comprueba qué shell y sistema operativo utilizas. La documentación oficial indica que la instalación nativa usa actualizaciones automáticas en segundo plano, mientras que las instalaciones con Homebrew y WinGet no se actualizan automáticamente.

Instrucción
# macOS · Linux · WSL
curl -fsSL https://claude.ai/install.sh | bash
Instrucción
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
Instrucción
Windows CMD:
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Homebrew:
brew install --cask claude-code

WinGet:
winget install Anthropic.ClaudeCode

Conviene usar los comandos de instalación tal como aparecen en la documentación oficial y no mezclarlos con scripts modificados arbitrariamente encontrados en Internet. Antes de ejecutarlos, vuelve a comprobar en la documentación oficial si han cambiado los requisitos actuales o los entornos compatibles de cada método de instalación.

03Comprobar la versión sin fijar un número concreto como valor esperado

Al terminar la instalación, abre una terminal nueva y comprueba con `claude --version`. Según la documentación oficial, se muestran el número de versión y «(Claude Code)». Como el número de versión puede cambiar con el tiempo, este artículo no fija una cifra concreta.

Instrucción
claude --version

Si aparece un mensaje indicando que no se encuentra el comando, en lugar de adivinar una ruta conviene revisar otra vez el paso de instalación y la guía de resolución de problemas de la documentación oficial. Como este texto no ejecutó realmente Claude Code, no afirma haber reproducido una pantalla concreta de error o de éxito.

04Crear una carpeta de práctica separada en lugar de usar un proyecto real

Es más seguro no hacer la primera ejecución directamente en una carpeta de investigación o en un repositorio de trabajo, sino crear una carpeta de práctica vacía. Aquí usamos solo una carpeta llamada vibe-expenses y el expenses.csv ficticio. Después de crear la carpeta, guarda el contenido CSV definido en el artículo anterior.

Instrucción
mkdir vibe-expenses
cd vibe-expenses
Instrucción
date,category,amount

2026-09-03,food,8500
2026-09-10,supplies,3200
2026-09-15,transport,1450
2026-10-02,food,9800

Guarda el archivo en UTF-8. En este paso no creamos summarize.py. El objetivo de la primera sesión no es «hacer que la IA programe de inmediato», sino practicar cómo leer y explicar la carpeta actual antes de que el usuario decida qué cambiar.

05Empezar en modo plan e iniciar sesión por primera vez

Claude Code puede iniciarse con `claude` dentro de la carpeta del proyecto y, en la primera ejecución, puede abrir el inicio de sesión en el navegador. Para un principiante, sin embargo, recomendamos empezar en modo plan en lugar de comenzar directamente con un flujo que permita modificar archivos. El modo plan es un modo de permisos orientado a lectura para revisar análisis y planes, y desde la línea de comandos puede iniciarse así.

Instrucción
claude --permission-mode plan

En la primera ejecución puede aparecer el proceso de inicio de sesión en el navegador. Si necesitas cambiar de cuenta, puedes usar `/login` dentro de la sesión. El modo de permisos predeterminado puede variar según la cuenta y el entorno, por lo que este artículo no afirma que «siempre sea Manual». Según la documentación oficial consultada el 2026-09-22, el modo inicial predeterminado de la terminal interactiva para los planes Pro, Max y Team es auto, mientras que para otros planes es Manual.

06Hacer tres preguntas de solo lectura antes de cambiar archivos

Cuando comience la sesión, no pidas de inmediato «créame el programa». Primero comprueba hasta qué punto entiende correctamente la carpeta actual. Claude Code puede leer por sí mismo los archivos que necesite y puede solicitar aprobación antes de modificar archivos o ejecutar comandos. En esta práctica no pedimos ninguna modificación; solo hacemos preguntas.

Instrucción
Indícame qué archivos hay en esta carpeta. No modifiques ningún archivo.

Explica los nombres de las columnas de expenses.csv y qué parece significar cada una. No modifiques ningún archivo.

Si fueras a crear una herramienta para calcular el total mensual de amount con este CSV, resume en tres puntos qué habría que comprobar antes de implementarla. Todavía no escribas código.

En la respuesta, comprueba como mínimo que no se haya interpretado mal el nombre del archivo actual ni las columnas del CSV. Si la IA menciona un archivo que no existe o propone una modificación o instalación no solicitada, pregunta primero por el motivo. Como las frases concretas de Claude Code pueden cambiar según el modelo y el momento, aquí no inventamos un diálogo correcto y lo presentamos como si fuera una salida real.

07Cerrar la sesión y pasar al siguiente artículo

Una vez alcanzado el objetivo de la primera sesión, ciérrala sin haber creado código. Dentro de la sesión se puede usar `/exit`, y también se puede salir pulsando Ctrl+D dos veces. `/help` muestra la lista de comandos; existen además comandos como `/clear`, `/resume`, `/compact` y `/rewind`, pero aquí solo comprobamos sus nombres sin ampliar la práctica.

Instrucción
/exit
  • Se comprobó la instalación con claude --version.
  • Se usó la carpeta de práctica vibe-expenses, no una carpeta real de trabajo.
  • expenses.csv contiene únicamente datos ficticios.
  • Se hicieron tres preguntas en modo plan sin modificar archivos.
  • La generación real de código se dejó para el siguiente artículo.

¿Qué es el vibe coding? Qué debe hacer la persona cuando delega código a la IA

Entendemos el vibe coding no como «decírselo con palabras y dejar que la IA lo haga todo», sino como una forma de trabajo en la que la persona define los requisitos y los criterios de comprobación y después revisa el resultado generado por la IA. Con una herramienta ficticia para sumar un CSV de gastos domésticos, organizamos en una sola nota la entrada, la salida, lo que no debe hacerse y cómo verificar el resultado.

Claude Code: planifica antes de editar y amplía funciones con el modo plan

A partir del ejemplo de añadir la opción `--by-category` a una herramienta ya funcional que suma gastos por mes, aprenderás a revisar primero el plan de cambios en el modo plan de Claude Code. Antes de implementar, fijarás el alcance de la modificación y el formato de salida; después de aprobar el plan, ejecutarás el código final para comprobar tanto los totales mensuales existentes como los totales por categoría.

Revisar con git lo que cambió la IA: del commit previo al diff y al commit final

Aprenderás un flujo mínimo para dejar un punto de referencia con git antes de que Claude Code modifique archivos y, después del trabajo, revisar los cambios reales con `git status` y `git diff`. Puedes pedir a la IA que explique el diff, pero el proceso se basa en que una persona compruebe el diff y los resultados de ejecución antes de hacer staging y commit directamente.

Corregir errores con Claude Code: reproducir → causa → cambio mínimo → volver a ejecutar

En lugar de limitarte a decirle a la IA que «da error», practicarás un flujo en el que primero reproduces el problema con la misma entrada, acotas la causa a partir del mensaje de excepción real y solicitas solo el cambio mínimo. Usaremos un CSV cuyo amount contiene una coma para reproducir un ValueError en Python y volveremos a ejecutar el código corregido para comprobar el resultado.
