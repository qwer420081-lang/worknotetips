01AI PPTを作る前に原文と発表目的を固定する

AIでPPT発表資料を作るとき、最初にすることはデザインを選ぶことではなく、原文から何を言えるのかという範囲を決めることです。今回の実習では、架空の図書館読書会に関する3つの記録文をもとに、6枚の発表資料構成と発表者ノートを作ります。日付や予算のようにまだ決まっていない内容は、AIが自然に補わないよう、プロンプトで明示的に制限します。

入力資料
S1. 2026年8月の図書館読書会には24人を招待し、実際の参加者は18人だった。
S2. イベント後、参加者18人のうち12人が匿名アンケートに1回ずつ回答し、そのうち9人が次回の会にも参加したいと答えた。
S3. 次回の会の日程と予算はまだ決まっていない。

原文から直接計算できる値は、参加率18÷24=75%と、アンケート回答者のうち次回参加希望の割合9÷12=75%です。一方、全参加者18人のうち何人が次回参加を希望しているかは分かりません。アンケートに回答しなかった参加者の意向が不明だからです。

  • 確定している事実：招待24人、実参加18人、アンケート回答12人、次回参加希望9人
  • 計算可能：参加率75%、回答者のうち次回参加希望75%
  • 計算不可：全参加者に占める次回参加希望の割合
  • 未定事項：次回の会の日程と予算

02事実の追加を防ぐ制約型プロンプトを書く

発表資料用のプロンプトでは、単に「PPTを6枚作って」と書くよりも、スライド枚数、順序、根拠の示し方、禁止する推論まで指定したほうが検証しやすくなります。特に数値を含む発表では、どの集団を分母として計算したのかを文章に残す必要があります。

プロンプト
以下の原文だけを使って、6枚の発表資料案を作成してください。

スライド順:
1. 目的
2. 参加
3. アンケート
4. 限界
5. 次にすること
6. 意思決定

各スライドには次の項目を書いてください。
- タイトル
- 1つのメッセージ：1文
- 根拠：S1、S2、S3のうち該当する番号
- 発表者ノート：発表者が話す2～3文
- 画面案：表、数値、簡単な図形など

制約:
- 原文にない日付、予算、理由、満足度、効果を作らないでください。
- 参加率は18/24=75%と表現してください。
- 次回参加希望は「アンケート回答者12人のうち9人、75%」と表現してください。
- これを「全参加者の75%が次回参加を希望した」と変更しないでください。
- 全参加者を基準にした希望率は、アンケート未回答者の意向が不明なため計算できないと明記してください。
- 日程と予算は未定のままにしてください。
- 事実と提案を文単位で分けてください。

原文:
S1. 2026年8月の図書館読書会には24人を招待し、実際の参加者は18人だった。
S2. イベント後、参加者18人のうち12人が匿名アンケートに1回ずつ回答し、そのうち9人が次回の会にも参加したいと答えた。
S3. 次回の会の日程と予算はまだ決まっていない。

036枚の発表資料の結果例を読む

以下の内容は、特定のAI製品を実行して得た結果ではありません。上の制約を満たすように編集者が手作業で作成した例です。実際にAIが作った案を使う場合も、同じ構成で原文と1行ずつ照合できます。

スライドタイトル1つのメッセージ根拠発表者ノート画面案
1. 目的読書会の結果を次の運営判断につなげる今回の発表の目的は、参加状況とアンケート結果を確認し、次回の会で決めるべき項目を整理することです。S1, S2, S3この資料ではイベントの成果を誇張して評価するのではなく、現在確認できる数値を整理することに重点を置きます。最後に、まだ決まっていない日程と予算を意思決定項目として残します。目的を1文で示し、6枚の流れを簡単な順序図で表示
2. 参加24人招待、18人参加2026年8月の読書会の参加率は75%でした。S1招待者数は24人で、実際の参加者は18人です。18を24で割ると、参加率は75%です。この数値は参加状況だけを示しており、満足度やイベントの効果を意味するものではありません。24人 → 18人と75%を大きな数値で表示
3. アンケート回答者12人のうち9人が次回参加を希望匿名アンケート回答者を基準にすると、次回参加希望の割合は75%でした。S2アンケートには12人が回答し、そのうち9人が次回の会への参加を希望しました。したがって、回答者基準では75%です。これを全参加者の割合に拡張して表現してはいけません。12人のうち9人を9/12または75%で表示
4. 限界回答者の結果を全参加者の結果に置き換えることはできないアンケートに答えていない参加者の意向が分からないため、全参加者の希望率は断定できません。S1, S2参加者は18人ですが、アンケート回答者は12人です。残りの参加者が次回の会に参加したいかどうかは原文にありません。したがって、9を18で割り、それを全参加者の希望率として示してはいけません。参加18人と回答12人を分けて示す簡単な図
5. 次にすること日程と予算を決めるための情報が必要次回の会の日程と予算はまだ未定のため、別途決定する必要があります。S3現在の記録だけでは、次のイベントの日程や予算を示すことはできません。候補日や予算案を新たに集めてから決定する必要があります。ここで候補を示す場合も、原文の事実ではなく提案であると表示する必要があります。日程：未定、予算：未定をチェック項目の形で表示
6. 意思決定確定した事実と未定項目を分けて決める確定している参加・アンケート数値は共有し、次回の会の日程と予算は別の意思決定項目として残します。S1, S2, S3確認できる事実は、参加率75%と、アンケート回答者のうち次回参加希望75%です。一方、全参加者基準の希望率、次回の日程、予算は確定できません。会議ではこの3項目を分けて扱うのが適切です。確定した事実と決定が必要な項目を2列に分けて表示
結果例
編集者が作成した結果例の要約
- 参加：24人招待、18人参加、参加率75%
- アンケート：12人回答、9人が次回参加希望、回答者基準75%
- 限界：全参加者のうち次回参加希望の割合は確認不可
- 未定：次回の会の日程、予算
- 発表構成：目的 → 参加 → アンケート → 限界 → 次にすること → 意思決定

注意：この例は実際のAI実行結果ではなく、検証方法を示すために編集者が作成した例です。

04数値と分母を原文に戻って再確認する

AI発表資料で特に危険な誤りの1つは、計算自体は正しくても分母が変わっているケースです。9÷12と9÷18は別の質問に対する計算です。原文から分かるのは、アンケート回答者12人のうち9人が次回参加を希望したという事実だけです。

誤った結果例
誤った例:
全参加者の75%が次回の読書会に参加したいと答えた。

この文は修正が必要です。75%の分母は全参加者18人ではなく、アンケート回答者12人です。正しい表現は「アンケート回答者12人のうち9人、つまり回答者の75%が次回参加を希望した」です。未回答者の意向が分からないため、全参加者のうちの希望率は断定できません。

確認リスト
数値チェックリスト
[ ] 招待人数24人が原文S1と一致しているか？
[ ] 参加人数18人が原文S1と一致しているか？
[ ] 参加率を18/24=75%と計算しているか？
[ ] アンケート回答人数12人が原文S2と一致しているか？
[ ] 次回参加希望9人が原文S2と一致しているか？
[ ] 希望率を9/12=75%と計算しているか？
[ ] 「回答者の75%」を「全参加者の75%」に変えていないか？
[ ] 日程と予算を勝手に埋めていないか？

05事実・解釈・提案を分け、画像と個人情報を確認する

発表資料案は、数値だけでなく文の性質も確認する必要があります。「参加率は75%だった」は原文から計算できる事実です。一方、「次回の会は土曜の午後がよい」や「予算を増やせば参加者が増える」といった文は、今回の原文では確認できません。必要な場合は、「提案」または「追加検討事項」として別に示す必要があります。

  • 事実：原文に直接書かれている内容、または原文の数値から直接計算できる内容
  • 解釈：事実の意味を説明する文。原文が支える以上に強い結論になっていないか確認する
  • 提案：次の日程、予算、運営方法など、新たに決める必要がある内容
  • 画像：自分で作成した図やグラフ、または利用許可を確認した画像を優先する
  • 機微情報：氏名、連絡先、会員番号、内部識別子など、発表に不要な情報はAIに入力する前に削除する
  • 匿名アンケート：匿名であることを理由に回答者の身元を推測したり、新しい個人情報を作ったりしない
確認リスト
内容チェックリスト
[ ] 各重要文にS1、S2、S3のいずれかを根拠として付けられるか？
[ ] 原文にない原因や効果を事実として書いていないか？
[ ] 未定の日程と予算を確定値として書いていないか？
[ ] 提案を「提案」「検討」「決定が必要」などとして事実と区別しているか？
[ ] 発表に不要な個人識別情報を削除したか？
[ ] 外部画像の利用許可を確認したか？
[ ] 可能な場合は、自作の表、数値カード、図形で情報を表現しているか？

06検証した案を発表ツールへ手作業で移す

この実習の最後の段階は、検証したテキストを実際の発表ツールへ手作業で移すことです。ここでは特定製品の自動生成機能やPPTX自動作成を前提にしません。まずテキスト案を確定し、その後、発表ツール側でレイアウトや視覚要素を人が調整します。

  • 1. 6枚のスライドのタイトルと1つのメッセージを先にコピーし、各ページの骨組みを作ります。
  • 2. 表の「画面案」を参考にして、数値カード、簡単な表、矢印など必要な要素だけを手作業で配置します。
  • 3. 検証済みのノートを発表者ノート欄へ移し、スライド本文に文章を詰め込みすぎないようにします。
  • 4. 75%が出てくる2枚のスライドで、それぞれの分母が24人と12人で異なることを再確認します。
  • 5. 「全参加者の次回参加希望率」のように、原文から確認できない文が残っていないか検索します。
  • 6. 日程と予算が引き続き「未定」または「決定が必要」と表示されているか確認します。
  • 7. 画像やアイコンは自分で作成したもの、または利用許可を確認したものだけを使い、不要な個人情報が画面に残っていないか最終確認します。

AI PPT作業では、スライドを早く埋めることよりも、原文と発表資料の間の追跡可能性を保つことが重要です。各スライドに根拠のS番号を残しておけば、数値が変わったり文が誇張されたりしたときに、原文へ戻って確認しやすくなります。最終発表資料では根拠番号を画面から隠す場合でも、編集時の検証メモには残しておくほうが安全です。

自分で確認する項目

架空の図書館読書会のS1～S3原文と、編集者が作成した6枚の発表資料例を使った文書検証実習

  • 18/24を自分で計算し、75%になることと、参加率の分母が招待者24人であることを確認します。
  • 9/12を自分で計算し、75%になることと、希望率の分母がアンケート回答者12人であることを確認します。
  • アンケート未回答者の意向が不明なため、全参加者基準の希望率を確定できないという説明が維持されていることを確認します。
  • 6枚の順序が、目的、参加、アンケート、限界、次にすること、意思決定になっていることを確認します。
  • 各スライド例に、タイトル、1つのメッセージ、根拠S番号、発表者ノート、画面案がすべて含まれていることを確認します。
  • 原文にない日付、予算、原因、効果が事実として追加されていないことを確認します。
  • 事実と提案が分けられ、画像の利用許可と機微情報削除の項目が含まれていることを確認します。
  • 検証済みの内容を人が発表ツールへ手作業で移す手順になっていることを確認します。
検証範囲の限界

本文の6枚の結果は、特定のAIサービスを実際に生成・実行して検証した出力ではなく、プロンプトと検証手順を説明するために編集者が作成した例です。この記事では、実際のPPTXファイル生成、特定の発表製品の機能検証、デザイン品質の評価は扱いません。
