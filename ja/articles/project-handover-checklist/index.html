対象読者人から人へプロジェクトを引き継ぐ際に、担当責任、ファイル保存場所、未解決作業を明確にするチェックリストが必要なチーム向けのガイドです。

準備するもの
  • Python 3.12 と、そのバージョンを起動できるターミナルコマンド。
  • UTF-8 CSV ファイルを保存できるテキストエディタまたは表計算ソフト。
  • スクリプトが outputs の下に新しいフォルダを作成できる作業フォルダ。
  • 必要なのは Python 標準ライブラリのみです: csv, pathlib.

01すべての引き継ぎ項目で答えるべき内容を定義する

役立つ引き継ぎチェックリストでは、次の担当者が、その項目が何か、誰が責任を持っているか、関連資料がどこにあるか、項目が完了しているか、何が未解決かを分かる必要があります。「files are on the drive」のようなメモだけでは、後からプロジェクトに参加する人には通常十分具体的ではありません。

この例では6つの fields を使用します: item_id, handover_item, owner, location, status, open_issue。status は READY または OPEN です。READY items は open_issue field が空でなければなりません。OPEN items は、何が未解決なのかを説明する必要があります。

Location は実際に辿れる内容にする

repository path、shared-drive folder、document name、equipment location など、別の人が実際に辿れる location を記録してください。somewhere in Drive や on my laptop のような表現は避けます。

02合成のプロジェクト引き継ぎチェックリストを作成する

以下の checklist は合成データであり、この記事のために作成したものです。handover_items.csv として保存してください。5つの handover items が含まれ、そのうち2つには checklist を受け入れる前に検出すべき問題を意図的に入れています。

csv

H001 から H003 は構造上 complete です。H004 は READY と表示されているのに owner がありません。H005 は open issue を説明していますが、bug list の location がありません。したがって、この例には validation problems が2件あります。

想定される合計は checklist items 5件、valid items 3件、invalid items 2件です。OPEN items は H003 と H005 の2件で、どちらにも空でない issue descriptions があります。したがって、この例の問題は issue text の欠落ではなく、responsibility と location information の欠落です。

この区別は重要です。未解決作業が明確に説明され、担当が割り当てられ、場所が分かる状態であれば、正当な open issues が残っていても project は handover 可能な場合があります。

04Python で引き継ぎチェックリストを検証する

次の script を check_handover.py として保存してください。required columns, duplicate IDs, owners, locations, allowed status values、status と open_issue field の整合性を確認します。元の checklist を変更せずに review report を書き出します。

python
import csv
from pathlib import Path

SOURCE = Path("handover_items.csv")
OUTPUT_DIR = Path("outputs") / "handover_check_result"
REPORT = OUTPUT_DIR / "handover_review.csv"
REQUIRED_COLUMNS = [
    "item_id", "handover_item", "owner", "location", "status", "open_issue"
]
VALID_STATUS = {"READY", "OPEN"}


def add_issue(issues, row_number, item_id, issue):
    issues.append({
        "row_number": row_number,
        "item_id": item_id,
        "issue": issue,
    })


def main() -> None:
    if not SOURCE.is_file():
        raise FileNotFoundError(f"Source CSV not found: {SOURCE}")
    if OUTPUT_DIR.exists():
        raise FileExistsError(f"Output folder already exists: {OUTPUT_DIR}")

    issues = []
    seen_ids = set()
    item_count = 0
    open_count = 0

    with SOURCE.open("r", encoding="utf-8-sig", newline="") as stream:
        reader = csv.DictReader(stream)
        if reader.fieldnames != REQUIRED_COLUMNS:
            raise ValueError(
                f"Header mismatch. Expected {REQUIRED_COLUMNS}, got {reader.fieldnames}."
            )

        for row_number, row in enumerate(reader, start=2):
            item_count += 1
            item_id = row["item_id"].strip()
            handover_item = row["handover_item"].strip()
            owner = row["owner"].strip()
            location = row["location"].strip()
            status = row["status"].strip()
            open_issue = row["open_issue"].strip()

            if not item_id:
                add_issue(issues, row_number, item_id, "MISSING_ITEM_ID")
            elif item_id in seen_ids:
                add_issue(issues, row_number, item_id, "DUPLICATE_ITEM_ID")
            seen_ids.add(item_id)

            if not handover_item:
                add_issue(issues, row_number, item_id, "MISSING_ITEM_NAME")
            if not owner:
                add_issue(issues, row_number, item_id, "MISSING_OWNER")
            if not location:
                add_issue(issues, row_number, item_id, "MISSING_LOCATION")
            if status not in VALID_STATUS:
                add_issue(issues, row_number, item_id, "INVALID_STATUS")
            elif status == "OPEN":
                open_count += 1
                if not open_issue:
                    add_issue(issues, row_number, item_id, "MISSING_OPEN_ISSUE")
            elif open_issue:
                add_issue(issues, row_number, item_id, "READY_HAS_OPEN_ISSUE")

    OUTPUT_DIR.parent.mkdir(parents=True, exist_ok=True)
    OUTPUT_DIR.mkdir()
    with REPORT.open("x", encoding="utf-8", newline="") as stream:
        writer = csv.DictWriter(
            stream,
            fieldnames=["row_number", "item_id", "issue"],
        )
        writer.writeheader()
        writer.writerows(issues)

    affected_items = len({row["item_id"] for row in issues})
    print(f"Checklist items: {item_count}.")
    print(f"Open items: {open_count}.")
    print(f"Validation issues: {len(issues)}.")
    print(f"Affected items: {affected_items}.")
    print(f"Report: {REPORT.as_posix()}")


if __name__ == "__main__":
    main()

06ファイルの存在だけでなく、引き継ぎ全体を確認する

  • handover 後に ownership が変わる場合でも、すべての item に明確に名前の付いた owner が1人いることを確認します。
  • 記載された各 location を開き、次の担当者が実際に access できることを確認します。
  • OPEN items については、unresolved issue、current status、next expected action を記載します。
  • READY items が comments, chat messages, private notes に unresolved work を隠していないことを確認します。
  • credentials は checklist に secrets を書くのではなく、承認された password または access-management process で引き継ぎます。
  • OUTPUT_DIR を変更せずに script を再実行します。以前の review を置き換えるのではなく FileExistsError で停止するはずです。

path が文法上存在していても、permissions がない、または参照 file が古い場合には役に立ちません。そのため checklist は、project を離れる人だけでなく、受け取る人にも確認してもらう必要があります。

07よくある引き継ぎ失敗を確認する

弱い handover entry不十分な理由
Owner: Team責任を持つ person または defined role がいない場合、responsibility が不明確です。
Location: Drive受け取る人は実際の file または folder をさらに探す必要があります。
Status: Doneteam の completion 定義が明確でなければ Done は曖昧です。
Open issue: Needs workproblem と next action が十分具体的ではありません。
Credentials included in CSV一般的な handover checklist は passwords や secrets を置く場所として適切ではありません。

file が存在するという理由だけで item を READY にしないでください。利用可能な handover には access、最新の documentation、ownership、受け取る人が unresolved decisions を理解していることも必要です。

08大きなプロジェクト向けにチェックリストを拡張する

実際の project では receiving_owner, due_date, repository branch, access_required, last_verified_date, dependency, contact person, equipment location, approval status, next milestone などの追加 fields が必要になる場合があります。transfer clarity を高める場合だけ fields を追加してください。

この script が検証するのは completeness と internal consistency であり、location が到達可能か、open issue description が技術的に正しいかではありません。access checks, file freshness, repository state, equipment condition, knowledge transfer には別の review が必要です。

checklist は version または date を付けて project records と一緒に保持してください。受け取る人が handover を確認した後は、元の transfer state を黙って書き換えるのではなく、その acceptance を別に記録します。
