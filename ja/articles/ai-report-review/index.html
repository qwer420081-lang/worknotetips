準備するもの
  • 確認対象の下書きレポートと、それに使われた元データを別々に用意します。
  • 元データの単位、対象期間、範囲、抽出日を確認します。アクセスできないものは検証不能として記録します。

01文の自信ではなく根拠を確認する

AIレポートが自然に読めても、数値や出典が正しいかは別に確認する必要があります。NISTの生成AIリスクに関するガイダンスでは、誤った内容だけでなく、推論や引用も作り出される可能性があると説明し、出力の来歴や引用を確認することを推奨しています。この記事では、数値を含む各文を分け、元データ、計算式、最終的な表現に結び付けて確認します。

確認してください

下書きとすべての数値は、この記事のために作成した合成例です。特定のAIサービスの実際の出力でも、実在企業の結果でもありません。

02文を3種類に分ける

種類例確認する根拠
元データの事実8月に1,500件の依頼が完了した元データの月、列、定義
計算結果完了件数が25 %増加した前月と当月の値、分母、計算式
解釈または提案AIによって速くなったため、利用を拡大すべきだ原因を切り分けるデータと意思決定基準

1つの文にこの3種類が混ざっている場合は、短い文に分けます。「依頼件数が増え、自動化が有効だった」という文では、前半は件数で確認できますが、後半には別の根拠が必要です。数値が正しくても、因果関係の説明まで正しいとは限りません。

03各文を確認する順序

  1. 確認する下書きをコピーし、数値、比率、日付、出典を含むすべての文に番号を付けます。
  2. 1文につき確認する主張を1つだけ残し、claim-log.txt に移します。
  3. 元データの場所と定義を書き留めます。URLしかない場合は、自分で文書を開き、表、ページ、基準日、図を確認します。
  4. 直接引用された値と計算された値を分けます。計算値については、分子、分母、単位、丸め規則を記録します。
  5. 元データから合計、変化率、比率、平均を再計算します。同じAIにもう一度正しいか尋ねるだけでレビューを終えないでください。
  6. verified、needs correction、insufficient evidence、unverifiable のいずれか1つを付けます。根拠が不足している文は、数字だけを変えて残すのではなく、主張の範囲を狭めます。
  7. 修正版とレビュー記録を一緒に保存し、元データが変わった場合は影響を受ける文から先に再確認します。

05比率と平均を再計算する

項目計算式確認値
完了件数の増加率(1500−1200)÷1200×10025.0 %
期限内完了率、7月・8月1080÷1200; 1380÷150090.0 %; 92.0 %
期限内完了率の差92.0−90.0+2.0 %p
2か月合計の完了率(1080+1380)÷(1200+1500)×100約91.1 %
1件当たり作業時間450×60÷1200; 525×60÷150022.5 min; 21.0 min
1件当たり時間の変化率(21.0−22.5)÷22.5×100約−6.7 %
1件当たりコスト3600000÷1200; 4200000÷1500KRW 3,000; KRW 2,800

2か月合計の率は、月ごとの率を単純平均するのではなく、元の分子と分母をそれぞれ合計して計算します。91.0 %と91.1 %が近く見えても、計算対象が異なる点が重要です。90 %から92 %への変化は2パーセントポイント（pp）で、相対的な増加率としては約2.2 %です。

作業時間はhoursで与えられているため、60を掛けてminutesに変換してから依頼件数で割ります。計算中は十分な精度を維持し、本文では小数第1位まで表示します。丸めた月別値だけから全体指標を再計算しないでください。

06リンク付きの文も元資料まで確認する

  1. 組織の公式ページまたは元データ提供者から文書を開きます。レポートに書かれたタイトル、著者、日付が実際の文書と一致するか確認します。
  2. 主張で使われた数値が、その表や段落に実際にあるか確認します。検索結果のスニペットだけで検証しないでください。
  3. 対象期間、対象集団、単位、標本か推定値か、改訂の有無を確認します。公開日と観測期間を混同しないでください。
  4. 下書きが元資料以上のことを主張していないか確認します。特定のサンプルでの変化が、すべてのチームに同じ効果があることを意味するわけではありません。
  5. アクセスできない、または裏付ける段落がない場合はunverifiableと記録します。もっともらしいタイトルやURLで不足した出典を埋めないでください。

この合成例の数値は source-data.json から来ています。NIST文書はレビュー手順の参考資料であり、上記の架空の月次数値を裏付ける出典ではありません。方法の出典と数値の出典は分けて記録してください。

07修正文と確認方法

text
검수 후 문장 — 합성 자료에 대한 설명이며 실제 성과가 아닙니다.
8월 처리 완료 건수는 1500건으로 7월 1200건보다 25.0 % 증가했다.
기한 내 완료율은 90.0 %에서 92.0 %로 2.0 %p 높아졌다.
두 달 전체 기한 내 완료율은 2460/2700×100으로 약 91.1 %다.

완료 건당 비용은 3000원에서 2800원으로 약 6.7 % 감소했다.
자료에는 AI 도입 여부, 작업 난이도, 인력 구성, 다른 변화 요인이 없다.
따라서 차이의 원인이나 확대 도입의 효과는 이 자료만으로 판단할 수 없다.
출처: source-data.json, months[0], months[1]; 설명용 합성 자료.

①、④、⑤は定義と計算を確認した後で残せます。②は2 %を2 ppに修正し、③は分子と分母を合計して再計算します。⑥はデータにない原因と提案を述べているため、削除するか、別の検証課題に移します。誤った文だけを記録するのではなく、残した文についても根拠の場所を記録し、次回の改訂時に再確認できるようにしてください。

  • 再計算値: 2,700 completed, 2,460 on time, overall rate 91.111… %
  • 単位確認: 450 hours = 27,000 minutes; 525 hours = 31,500 minutes
  • コスト確認: total cost +16.666… %, cost per request −6.666… %
  • 結論の範囲: 2か月間の差は記述できますが、AIの因果効果は確認されていません

08よくある誤りと限界

  • 分母が変わっているのに同じ指標として比較しないでください。Received requests と completed requests は分母が異なります。
  • 元データにない項目を0や平均値で埋めないでください。
  • 総量の増加と1件当たり指標の減少は同時に起こり得るため、矛盾として削除しないでください。
  • 公式文書へのリンクがあるという理由だけで、その文書が述べていない主張を承認しないでください。
  • 計算を確認したことを、元データの真実性、標本の代表性、法的・財務的判断まで確認したこととして扱わないでください。

ダウンロードには README.txt、source-data.json、draft-for-review.txt、corrected-summary.txt、claim-log.txt、expected-checks.json が含まれます。数値はローカルのPythonで再計算されました。これは実在するAIサービスやレポート生成システムの正確性を評価するものではありません。参考資料は2026年9月19日に公式ページで確認されました。

実行・検証の記録

  • 完了件数と期限内完了件数の合計、月別・全体の率、変化率を確認

  • 確認済みの値を expected-checks.json に保存し、本文に表示された値と比較
検証範囲の限界
  • 合成デモデータのみを確認
  • 実際のAIサービスの呼び出し、実在組織のデータ検証、因果効果の分析は実施していません
