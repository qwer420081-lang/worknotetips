Claude Codeのインストールと初回実行：コードを変える前にまず質問する

OSに合ったClaude Codeのインストールコマンドとアカウント条件を確認し、架空の練習フォルダーで最初のセッションを始めます。すぐにコードを生成するのではなく、planモードでフォルダーとCSVを読む3つの質問だけを試してから安全に終了することに焦点を当てます。

01インストール前にアカウントと練習範囲を確認する

Claude Codeは、無料で使えることを前提に説明すべきではありません。この記事の基準にした公式ドキュメントでは、Claude Pro・Max・Team・Enterpriseのサブスクリプション、Claude ConsoleのAPIプリペイドクレジット、または対応クラウドプロバイダーがアカウント経路として案内されています。どの方法が自分のアカウントに該当するかは、インストール前に公式ドキュメントと実際のアカウント画面で確認します。この記事では価格や特定のバージョン番号を独自に記載しません。

準備項目確認する内容この記事での選択
アカウント対応するClaudeサブスクリプション・Console・クラウドプロバイダーのうち該当する経路無料とは仮定しない
練習フォルダー実際の業務フォルダーと分けるvibe-expensesを使用
データ個人情報を含まない架空ファイルexpenses.csvを使用
権限最初は変更より読み取り・計画を中心にするplanモードを推奨

ネイティブWindowsではGit for Windowsのインストールが推奨されています。Git for Windowsがない場合、Claude CodeはPowerShellをシェルツールとして使用できます。Gitの使い方自体は第6回で扱うため、今回はインストール環境と最初のセッションだけに集中します。

02OSに合った公式インストールコマンドを使う

推奨されるネイティブインストールコマンドはOSごとに異なります。以下のコマンドをコピーするときは、まず自分が使っているシェルとOSを確認します。ネイティブインストールではバックグラウンド自動更新が使われますが、HomebrewとWinGetによるインストールは自動更新されないと公式ドキュメントに案内されています。

プロンプト
# macOS · Linux · WSL
curl -fsSL https://claude.ai/install.sh | bash
プロンプト
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
プロンプト
Windows CMD:
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Homebrew:
brew install --cask claude-code

WinGet:
winget install Anthropic.ClaudeCode

インストールコマンドは公式ドキュメントで確認した形をそのまま使い、インターネット上で独自に改変されたインストールスクリプトを混ぜない方が安全です。インストール方式ごとの最新要件や対応環境が変わっていないか、実行前に公式ドキュメントで再確認します。

03バージョンは確認するが、特定番号を期待値にしない

インストールが終わったらターミナルを開き直し、`claude --version`で確認します。公式ドキュメントでは、バージョン番号と'(Claude Code)'が出力されます。バージョン番号は時期によって変わる可能性があるため、この記事では特定の数字を書きません。

プロンプト
claude --version

コマンドが見つからないというメッセージが出た場合は、パスを勝手に推測するのではなく、インストール手順と公式ドキュメントのトラブルシューティング案内を再確認します。この原稿ではClaude Codeを実際には実行していないため、特定のエラー画面や成功画面を再現したとは書きません。

04実際のプロジェクトとは分けた練習フォルダーを作る

最初の実行を研究フォルダーや業務リポジトリでいきなり行うのではなく、空の練習フォルダーを作る方が安全です。ここではvibe-expensesというフォルダーと架空のexpenses.csvだけを使います。フォルダーを作った後、前の記事で決めたCSV内容を保存します。

プロンプト
mkdir vibe-expenses
cd vibe-expenses
プロンプト
date,category,amount
2026-09-01,food,12000
2026-09-03,transport,1450
2026-09-03,food,8500
2026-09-10,supplies,3200
2026-09-15,transport,1450
2026-10-02,food,9800

ファイルはUTF-8で保存します。この段階ではsummarize.pyを作りません。最初のセッションの目的は「AIにすぐコーディングさせる」ことではなく、現在のフォルダーを読んで説明させた上で、ユーザーが何を変えるかを決める練習です。

05planモードで開始して初回ログインする

Claude Codeはプロジェクトフォルダーで`claude`を実行して開始でき、初回起動時にはブラウザでログインします。ただし初心者には、最初から変更できる流れよりplanモードで始めることを推奨します。planモードは読み取りを中心に分析と計画を確認するための権限モードで、コマンドラインでは次のように開始できます。

プロンプト
claude --permission-mode plan

初回実行ではブラウザログイン手順が表示されることがあります。アカウントを変更する必要がある場合は、セッション内で`/login`を使用できます。権限モードのデフォルトはアカウントや環境によって異なる場合があるため、この記事では「常にManualがデフォルト」と断定しません。公式ドキュメント（2026-09-22確認）では、Pro・Max・Teamプランの対話型ターミナルのデフォルト開始モードはauto、その他のプランはManualと説明されています。

編集例
[編集例 · 実際の応答ではありません]
初回実行では、ブラウザログインや権限に関する案内が表示される場合があります。実際の画面文言や順序はインストール時期やアカウントによって変わる可能性があるため、現在の画面と公式ドキュメントを基準に確認してください。

06ファイルを変える前に読み取り専用の質問を3つ試す

セッションが始まっても、すぐに「プログラムを作って」とは言わず、現在のフォルダーをどれだけ正確に理解しているかから確認します。Claude Codeは必要なファイルを自分で読み、ファイル変更やコマンド実行の前に承認を求めることがあります。今回の練習では変更を依頼せず、質問だけをします。

プロンプト
このフォルダーにどんなファイルがあるか教えてください。ファイルは変更しないでください。

expenses.csvの列名と、それぞれの列が何を意味しているように見えるか説明してください。ファイルは変更しないでください。

このCSVで月別のamount合計を計算するツールを作るとしたら、実装前に確認すべきことを3つに整理してください。まだコードは作らないでください。

回答では、少なくとも現在のファイル名とCSV列を読み間違えていないか確認します。AIが存在しないファイルに言及したり、望んでいない変更やインストールを提案したりした場合は、まず理由を尋ねます。実際のClaude Codeがどのような文で答えるかはモデルや時期によって変わるため、この記事では架空の正解会話を作って実際の出力のようには示しません。

質問人が確認するポイント問題があれば
フォルダーには何があるかexpenses.csvを実際のファイルとして認識しているか存在しないファイルを挙げたら一覧の根拠を再確認する
CSVの列は何かdate, category, amountを正確に読んでいるか列名を推測したら元ファイルと照合する
実装前の確認事項は何か入力・出力・制約を先に確認しているかすぐ変更しようとしたら計画だけを依頼する

07終了して次の記事へ進む

最初のセッションの目標を達成したら、コードを作らないまま終了します。セッションでは`/exit`を使え、Ctrl+Dを2回押して終了することもできます。`/help`でコマンド一覧を確認でき、`/clear`, `/resume`, `/compact`, `/rewind`などのコマンドもありますが、今回は機能名だけ確認し、作業範囲は広げません。

プロンプト
/exit
  • claude --versionでインストール確認を終えた。
  • 実際の業務フォルダーではなくvibe-expenses練習フォルダーを使った。
  • expenses.csvには架空データだけが含まれている。
  • planモードでファイルを変更せず3つの質問をした。
  • 実際のコード生成は次の記事に回した。

次の記事では、これまでに作った要件とこの練習フォルダーを使って、summarize.pyを実際に作る流れを扱います。そのときは入力例、期待出力、標準ライブラリだけを使うという制約を1つの依頼文に入れ、生成されたPythonコードを別途実行して結果を検証します。

自分で確認する項目

Claude Code公式ドキュメント（2026-09-22確認）を基準に作成 · Claude Codeの実行なし · Python実行コードなし

  • macOS・Linux・WSL、Windows PowerShell、Windows CMDのネイティブインストールコマンドが公式ドキュメントと一致するか確認
  • HomebrewとWinGetの代替インストールコマンド、および自動更新の違いを公式ドキュメントと照合
  • claude --version, claude --permission-mode plan, /login, /exitのコマンド表記が公式ドキュメントと一致するか確認
  • 無料で使えると断定せず、対応するアカウント経路だけを示しているか確認
  • Claude Codeの画面・応答に該当する編集例が'[編集例 · 実際の応答ではありません]'で始まっているか確認
  • Python実行コードが含まれていないのに、Pythonで結果検証を行ったと誤って主張していないか確認
検証範囲の限界

この記事の作成過程ではClaude Codeをインストールまたは実行していません。インストールコマンドと機能説明は2026-09-22に確認したClaude Code公式ドキュメントに従っており、実際のインストール時点の対応環境・アカウント条件・画面文言は公式ドキュメントで再確認する必要があります。

バイブコーディングとは？AIにコードを任せるとき人がすべきこと

バイブコーディングを単に「言葉で頼めばAIが勝手に作ってくれるもの」と捉えるのではなく、人が要件と確認基準を決め、AIが作った結果を点検する作業方法として理解します。架空の家計簿CSV集計ツールを例に、入力・出力・してはいけないこと・確認方法を1ページのメモに整理します。

Claude Codeで最初のツールを作る：家計簿CSVの月別合計

これまでに作った架空のexpenses.csvと要件メモを使い、最初の小さなPythonツールを作る流れを練習します。依頼文に入力例・期待出力・制約をまとめて入れ、完成したsummarize.pyをClaude CodeではなくGPTチャットのPythonツールで実際に実行し、結果を確認します。

CLAUDE.mdでプロジェクトのルールを伝える

毎回の依頼で繰り返していた実行コマンド・データ規則・禁止事項・確認方法を、プロジェクトのCLAUDE.mdに簡潔に整理します。`/init`が下書きを作る機能と、ファイル配置ごとの用途を区別し、家計簿CSVの例に合う35行のルールファイルを完成させます。

Claude Codeですぐ直さず、まず計画から：planモードで機能を拡張する

すでに動作している家計簿の月別集計ツールに`--by-category`オプションを追加する例を通じて、Claude Codeのplanモードで先に変更計画を確認する方法を学びます。実装前に変更範囲と出力形式を固定し、承認後に完成コードを実行して、既存の月別合計とカテゴリ別合計を両方確認します。

gitでAIの変更内容を確認する：作業前コミットからdiffとコミットまで

Claude Codeがファイルを修正する前にgitで基準点を残し、作業後は`git status`と`git diff`で実際の変更内容を読む流れを学びます。AIにdiffの説明を頼むことはできますが、説明だけを信じず、人がdiffと実行結果を確認してから自分でステージングとコミットを行う手順を使います。

Claude Codeでエラーを直す：再現 → 原因 → 最小修正 → 再実行

AIに「エラーが出ます」とだけ伝えるのではなく、同じ入力で問題を再現し、実際の例外メッセージを根拠に原因を絞ってから最小限の修正だけを依頼する流れを練習します。amountにカンマが入ったCSVを使ってValueErrorを実際にPythonで再現し、修正コードも再実行して確認します。

Claude Codeを安全に使う：権限モード・チェックポイント・秘密情報

Claude Codeがファイルを読み取り、修正し、コマンドを実行できることを前提に、初心者が作業前・作業中・作業後に確認すべき安全上のポイントを整理します。権限モードの違い、チェックポイントでは復元できない変更、gitとの役割の違い、秘密情報を入れない原則を一つのチェックリストにつなげます。
