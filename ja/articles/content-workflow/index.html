対象読者小規模なチュートリアルサイトやチームのナレッジ文書を共同運営する執筆者とレビュー担当者

準備するもの
  • ダウンロードした content-register.csv と README.txt を用意します。
  • 管理者が、チームで使用する Google アカウントとファイル所有者を決定します。この記事ではアカウントの作成や接続は行っていません。
  • 下書き、レビュー、公開の役割と、status を変更する基準について合意します。

011つの記事の次のアクションを1行にまとめる

トピック一覧だけでは、どの下書きがレビュー中なのか、何が公開を妨げているのか把握しにくくなります。この例では、article ID, audience, deliverable, writer, reviewer, status, evidence, privacy check, approval date, published URL, release version を1行に結び付けます。タイトルが変わっても article ID は変えず、再び記録を探すためのキーとして使用します。

確認してください

CSV 内の EX-001 から EX-004 は合成デモサンプルです。approval statuses と dates も例であり、実際の承認または公開記録ではありません。CSV には dropdowns, permissions, version history は含まれていません。

02最初に列と status の意味を定義する

列グループ記録する内容
Article ID · title · audience · deliverableどの問題を、誰のために解決し、何を提供するか
Writer · reviewer · review due date確認すべき役割と日付
Status · next action現在の段階と、次の担当者が行うこと
Evidence · privacy check公式資料または合成例の説明と、確認結果
Approval date · published URL · release version承認された日時と、実際に公開された結果

使用する status は idea, drafting, in review, changes requested, approved, published, on hold のいずれか1つだけです。approved はレビューが完了したというチーム内の記録であり、published はサイトに反映して結果を確認したという記録です。この区別は私たちが設定した運用ルールであり、Sheets に組み込まれた承認システムではありません。

03CSV をインポートして dropdowns を設定する

  1. 管理者が Google Sheets で新しい管理用シートを用意し、File > Import からローカルの content-register.csv を選択します。import location と separator を確認し、既存の管理シートを誤って置き換えないでください。
  2. インポート後、14個の header columns、4件の sample rows、韓国語テキスト、空欄の approval date と published URL columns が保持されていることを確認します。この記事では実際の Google Sheets import はテストしていません。
  3. review due date と approval date が日付として認識されていることを確認し、YYYY-MM-DD で表示します。article ID はテキスト識別子として保持します。
  4. status column の data cells を選択し、Insert > Dropdown または Data > Data validation で7つの statuses を登録します。1行につき1つの status だけを許可します。
  5. privacy check column には not checked, needs changes, done を登録します。dropdown list にない値に対する設定も確認します。
  6. sample で動作を確認した後、合成 rows を削除するか、実際の records と混同しないよう別の practice copy に残します。

Google の公式ヘルプでは file import と cell dropdowns を別機能として説明しています。CSV は値だけを保持するため、これらの設定はインポート後に追加する必要があります。ファイルがすでに自動同期や接続設定まで完了しているように説明しないでください。

04filter views で自分の作業だけを見る

reviewer は status が in review の行を先に見たい場合があり、writer は自分の changes-requested rows を先に見たい場合があります。desktop Sheets では Data > Create filter view を使用し、status と owner の条件を選び、「Awaiting review」や「My changes」などの views を保存します。通常の filter は共有ファイルの他のユーザーにも見える場合があるため、個人作業の整理には filter views を使用します。

  • filter は行を非表示にするだけです。削除したり、permissions を制限したりする機能として扱わないでください。
  • 1つの列だけを単独で sort すると titles と owners の対応がずれる可能性があるため、管理対象の範囲全体が sort に含まれていることを確認します。
  • due date が空欄の行も別途確認します。filter に表示されないからといって完了したことにはなりません。
  • view permission で作成した temporary filter view は保存されない場合があるため、必要な management role と保存状態を確認します。

05共有権限と version history を管理する

ファイル所有者は、general access を restricted に保ち、特定の人だけを追加することを検討してください。writers は editors、feedback だけを残す reviewers は commenters、閲覧だけの stakeholders は viewers にできます。commenters はセル内の status を直接変更できないため、review feedback を受け取った editor が status と approval date を記録するという運用を決めます。管理者は実際の作業上の必要性に応じて permissions を付与します。

edit permission を持つユーザーは、version history で以前の状態と変更者を確認し、重要な時点に名前を付けられます。これは承認直前の状態を探すのに役立ちますが、site files の version history と同じものではありません。以前の version を復元すると他の編集まで取り消す可能性があるため、実行前に影響を確認します。CSV をダウンロードしても sharing permissions や version history は引き継がれません。

06承認からサイト更新までの手動フロー

  1. reviewer が sources, example results, sensitive information を確認し、change requests または approval feedback を残します。
  2. feedback を反映した draft を基に、editor が status を approved に変更し、approval date を記録します。
  3. publisher が approved content をサイトの content JSON と download assets に手動で反映します。この例では Sheets からサイトへの automatic CMS sync はありません。
  4. 変更した article の structure, links, examples, page display を確認してから deploy します。サイトの audience が owner-private の場合、結果もその access scope 内に留まります。
  5. deployed page を確認した後、実際の published URL と release version を記録し、status を published に変更します。public publishing が必要な場合は、サイトの audience を public に切り替え、access を別途確認する必要があります。
  6. 変更が必要になった場合は同じ article ID を保持し、status を changes requested または in review に戻し、next action に理由を記録します。

「Sheets で status を approved に変更するとサイトが更新される」といった自動動作は実装されていません。この tracking sheet は、誰がどの draft を承認し、それがどの release に入ったかを人が関連付けて記録するためのものです。

07合成サンプルで運用ルールを確認する

SampleStatus · check今必要な action
EX-001Idea / not checked合成例の draft を作成する
EX-002Drafting / not checkedhandover items を記入する
EX-003In review / needs changesinternal paths を削除した後に再レビューする
EX-004Approved / doneJSON に反映し、verify, deploy する; published URL はまだ空欄

EX-004 には published URL も release version もないため、published として数えません。逆に、link を追加しただけで review を省略することもできません。公開前に、人が approval date, evidence, privacy check result がすべて存在することを確認します。CSV には、これらの判断を強制する formulas や automation は含まれていません。

  • 同じ article ID が2回出現していないことを確認します。
  • status が published の rows では、実際の link が開き、正しい draft であることを確認します。
  • filters を解除し、on-hold, undecided, unassigned rows が欠落していないことを確認します。
  • sharing list と general access を一緒に確認します。
  • test copy で、どの roles が version history を確認でき、どの roles が comments だけを残せるか確認します。

08ダウンロードファイルと検証範囲

content-register.csv は14列と4行の合成データを持つローカルテンプレートです。README.txt, column-guide.txt, workflow-checklist.txt には、インポート後に適用する設定と status rules が含まれています。ローカルファイルの UTF-8 encoding、row and column counts、duplicate article IDs、allowed statuses、samples の blank published URLs は確認しました。実際の Google Sheets import と dropdown, permission, version history operations はテストしていません。

アカウントや Google Drive files は作成・接続しておらず、site checkout も変更していません。organization accounts では、sharing scope が admin policy によって制限される場合があります。公式ヘルプページは 2026年9月19日に確認しており、menu labels は display language や product updates によって異なる場合があります。
