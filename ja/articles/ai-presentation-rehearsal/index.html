AIで発表練習用の質問と回答を準備する

すでに整理された架空の発表資料を基に、想定聴衆質問6つと根拠、短い回答、分からない場合の確認計画を作る実習です。発表構成の作成やAI音声評価ではなく、限られた根拠を誇張せず質問に答える練習に焦点を当てます。

対象読者発表前に想定質問を準備し、数字を誇張しない回答練習をしたい初心者

準備するもの
  • 発表構成そのものを新しく作る実習ではありません。
  • 実際の発表音声や動画分析は行いません。
  • 架空の数値S1〜S3のみを根拠として使用します。

01発表練習に使用する元の根拠を固定する

今回の実習では、発表内容を新たに作るのではなく、すでに与えられた数字と未定項目だけを使って質問対応を準備します。招待人数と参加人数、匿名アンケート回答者と再参加希望回答者では母集団が異なるため、割合の分母を正確に区別する必要があります。

入力資料
[架空の発表根拠]
S1: 招待24人、実際の参加18人。
S2: 参加者のうち匿名アンケート回答者は12人で、そのうち再参加希望は9人。
S3: 次回プログラムの日付と予算はまだ未定。

計算可能な値:
- アンケート回答者のうち再参加希望の割合: 9/12 = 75%

注意:
- 75%はアンケート回答者12人を基準とした値である。
- 参加者18人全体の75%が再参加を希望したと言ってはいけない。
- 招待者24人全体にも同じ割合を適用してはいけない。
- 実際の発表に対するAI音声評価を実施したと主張しない。
source ID確認された内容言えない内容
S1招待24人、参加18人不参加理由や参加者満足度
S2回答者12人中、再参加希望9人回答していない6人の意向
S3次回日付と予算は未定確定日程や確定予算

02想定聴衆質問6つを元の根拠につなげる

良い想定質問は、発表者が分からない内容を無理に埋めさせるのではなく、どの根拠まで答えられるかを練習できるものです。そのため各質問にS1、S2、S3のどの資料が関連するか表示し、資料が不足している場合はその事実を回答の中に残すよう依頼します。

プロンプト
以下の架空の発表根拠だけを使って、発表後に出る可能性がある想定聴衆質問を6つ作ってください。

S1: 招待24人、参加18人。
S2: 参加者のうち匿名アンケート回答者12人、そのうち再参加希望9人。
S3: 次回日付と予算は未定。

各質問について次の4項目を書いてください。
1. 想定質問
2. 元の根拠source ID
3. 発表者が言う短い回答
4. 現時点で分からない場合の確認計画

注意:
- 9/12 = 75%はアンケート回答者基準であると明記してください。
- 75%を参加者18人全体や招待者24人全体の結果へ拡大しないでください。
- 入力にない理由、満足度、費用、日付を作らないでください。
- 発表構成を新しく作らないでください。
- 実際のAI音声評価を実施したと書かないでください。

03質問・根拠・短い回答・確認計画の表を作る

以下の表は、実際の聴衆がした質問の記録ではなく、発表練習のための編集例です。回答は可能な限り短く保ちながら根拠の範囲を明確にし、S3のように分からない内容は「未定」と答えた後、どの資料を確認するか決めます。

結果例
[AI支援で作成・確認した編集例 — 実際の発表結果やAI音声評価ではありません]

想定質問は合計6つ準備する。
数字に関する回答では、招待者24人、参加者18人、アンケート回答者12人、再参加希望回答者9人をそれぞれ異なる集団として区別する。
75%という表現を使うときは、必ず「アンケート回答者12人のうち」と付ける。
次回日程と予算は現在未定のため、推定値を作らない。
想定聴衆質問元の根拠短い回答分からない場合の確認計画

048分の練習時間を説明・質問・まとめに分ける

質問と回答を作ったら、実際に声に出して話してみる時間が必要です。ここでは、4分の説明、3分の質問、1分のまとめで合計8分の練習計画を立てます。これは実際の発表時間が正確にこの通りになるという意味ではなく、練習用の配分です。実際の所要時間は人が時計を見ながら直接測り、調整する必要があります。

区間計画時間練習する内容人が確認すること
説明4分S1〜S3の重要な数字と未定項目を説明実際に話した時間を直接計測
質問3分想定質問6つのうち一部を選んで短く回答数字の分母を間違えていないか確認
まとめ1分確定事実と今後確認する項目を分ける新しい結論を付け加えていないか確認
合計8分練習用の時間配分実測後に人が調整

AIが「4分相当」と書いたからといって、実際の話す時間が4分になるとは限りません。話す速度、間、質問の長さによって変わるため、この部分は人が実測する必要があります。

05数字の誇張と未定情報の生成を見つけて修正する

発表練習で最も注意すべき誤りは、限定された調査結果を参加者全体に拡大したり、未定の内容を自然に補ったりすることです。以下の例は、数字自体は一部合っているものの、分母と未定状態を誤って扱った場合です。

誤った結果例
[誤った編集例]
参加者の75%が次のプログラムにも再参加したいと答えました。高い再参加意向が確認できたため、次回プログラムは来月の同じ曜日に実施予定で、予算も従来と同じ水準で確定する予定です。

9人は参加者18人全体の75%ではなく、アンケート回答者12人のうち75%です。回答していない参加者6人の意向は分かりません。また、S3では次回日付と予算が未定となっているため、「来月の同じ曜日」や「従来と同じ水準の予算」を追加する根拠はありません。

プロンプト
回答を元の根拠に合わせて書き直してください。
- 75%の分母がアンケート回答者12人であると明記してください。
- 同じ割合を参加者18人全体に一般化しないでください。
- 招待者24人にも一般化しないでください。
- 次回日付と予算は未定のまま維持してください。
- 入力にない不参加理由、満足度、費用、日程を作らないでください。
- 分からない質問には「現在の資料では分からない」と答え、何を確認するか書いてください。
- 実際の発表音声をAIが分析または評価したと主張しないでください。

06発表直前に人が確認するチェックリスト

最後に、想定質問表を読みながら、すべての数字の分母とsource IDを確認します。実際の発表練習では、人が直接時間を測り、回答が長くなれば短くし、分からない質問に推測で答えない練習をします。この記事の結果例はAI支援で作成・確認した編集例であり、実際の発表成果、聴衆反応、AI音声評価の精度、または特定製品の機能を検証した結果ではありません。

確認リスト
[読者確認チェックリスト]
□ 招待24人と参加18人を区別したか?
□ アンケート回答者が参加者のうち12人であることを維持したか?
□ 再参加希望9人が回答者12人のうち9人であることを確認したか?
□ 9/12 = 75%を回答者基準だと説明しているか?
□ 75%を参加者18人全体に適用していないか?
□ 75%を招待者24人全体に適用していないか?
□ 次回日付を未定のまま維持したか?
□ 予算を未定のまま維持したか?
□ 想定質問が6つあるか?
□ 各質問に元の根拠、短い回答、確認計画があるか?
□ 4分説明 + 3分質問 + 1分まとめ = 8分であることを確認したか?
□ 実際の練習時間は人が直接測るようにしているか?
□ 実際のAI音声評価を実施したと主張していないか?

自分で確認する項目

編集例の確認範囲: S1〜S3の数値と未定状態、9/12=75%の分母、想定質問6つ、4+3+1=8分の時間計画が互いに整合しているか確認しました。

  • 招待24人・参加18人を区別
  • アンケート回答者12人・再参加希望9人を区別
  • 75%をアンケート回答者基準としてのみ表現
  • 想定聴衆質問6つで構成
  • 日付と予算を未定のまま維持
  • 4分説明・3分質問・1分まとめで8分を確認
  • 実際の所要時間は人が直接測定するよう案内
  • AI音声評価を実施したという主張なし
検証範囲の限界

実際の発表、聴衆からの質疑、音声分析、または特定AI製品の評価機能を実行・検証していません。提示した質問と回答は架空の根拠を利用した編集例であり、実際の発表成果や聴衆反応を予測するものではありません。

同じイベント案内のV1とV2をAIに提示し、5つの比較項目を変更・追加・削除・同一に分けて確認する実習です。削除された文を勝手に解釈せず、文書に実際に記載されている差分だけを記録する方法を学びます。

短いお知らせ文から6つのFAQを作り、根拠がある質問にはsource IDを付け、料金・返金・キャンセル待ちのように原文にない内容は勝手に答えを作らない方法を練習します。

AIで自由記述の意見をテーマ別に整理する：複数ラベルと分類保留を扱う

6つの短い自由記述意見を決められたテーマに分類し、1つの意見に2つのテーマが含まれる場合は複数ラベルを許可する実習です。ラベル合計が回答者数を上回ることがある理由と、根拠のない満足度や感情の強さを推測しない方法も確認します。

AIで難しい利用案内をやさしい言葉に直す：条件・例外・否定・期限を保つ

架空の資料貸出案内4文を分かりやすい表現に直しながら、登録会員という条件、7日の期限、予約資料は延長不可、非予約資料は1回の延長申請が可能だが承認は確定ではないという重要条件を失わない方法を練習します。

AIで調査質問と検索計画を作る

漠然とした調査目標を事実質問・経験質問・判断質問に分け、何をどこで確認すべきか検索計画を作る実習です。AIに検索結果を作らせるのではなく、確認すべき資料と未確認項目を先に整理します。

AIで利用者調査のインタビュー質問を作る

架空の申込フォーム利用体験を調べるための15分インタビュー質問をAIと設計する実習です。誘導質問を最近の実際の行動に関する中立的な質問へ修正し、まだ実施していないインタビューの予想回答を実際の証拠として扱わない方法を扱います。

制約条件を決めてAIでアイデアを発想する

参加人数、時間、印刷物、購入可否、使用機材などの制約条件を先に固定し、AIに互いに異なる4つの代案を発想させる実習です。どのアイデアが最も良いか決めるのではなく、各案が条件を守っているか確認し、条件が変わったときに再依頼する方法を扱います。
