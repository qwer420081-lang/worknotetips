AIで利用者調査のインタビュー質問を作る

架空の申込フォーム利用体験を調べるための15分インタビュー質問をAIと設計する実習です。誘導質問を最近の実際の行動に関する中立的な質問へ修正し、まだ実施していないインタビューの予想回答を実際の証拠として扱わない方法を扱います。

対象読者サービスや手続きを改善する前に、短い利用者インタビュー質問を作りたい初心者

準備するもの
  • 採用面接ではなく、利用体験調査の場面を前提とします。
  • 実際の個人情報を入力する必要はありません。
  • インタビューはまだ実施していないという状態を維持します。

01インタビューの目的と質問しない範囲を先に固定する

今回の実習は、架空のプログラム申込フォームを改善するための利用者調査です。目的は、最近の申込過程で実際に難しかった点を把握することです。インタビュー時間が短いため、あらゆる意見を聞くのではなく最近の行動を中心に質問し、個人情報・健康情報・所得情報のように目的に不要な情報は尋ねません。

入力資料
[架空のインタビュー設計メモ]
S1: 目的は、最近の申込過程で利用者が経験した難しさを把握することである。
S2: インタビュー時間は合計15分である。
S3: 個人情報、健康情報、所得情報は尋ねない。

時間配分:
- 導入 2分
- 経験質問 8分
- 改善質問 3分
- まとめ 2分
合計 15分

採用面接ではなく、申込フォームの利用体験調査である。
source ID内容質問設計への影響

S2合計15分質問数と追加質問を制限

この段階で重要なのは、「利用者は申込フォームを不便だと感じている」とあらかじめ決めつけないことです。S1は難しさがあったかを確認する目的であり、難しさが必ずあったという事実ではありません。

02誘導質問を最近の実際の行動に関する中立的な質問へ変える

誘導質問は、回答者を調査者が期待する方向へ導くことがあります。「申込フォームが複雑すぎましたよね?」と聞くより、最近の申込状況を思い出してもらい、どの段階で止まったり再確認したりしたかを尋ねる形に直します。

プロンプト
次の条件で利用者インタビュー質問を作ってください。

S1: 最近の申込過程で利用者が経験した難しさを把握する。
S2: 合計15分である。
S3: 個人情報、健康情報、所得情報は尋ねない。

時間は導入2分、経験質問8分、改善質問3分、まとめ2分で構成してください。
要件:
1. 最近の実際の申込行動を尋ねる中立的な質問を優先してください。
2. 「不便でしたよね?」「もっと簡単にすべきではないですか?」のような誘導質問は使わないでください。
3. 予想回答を実際の利用者発言のように作らないでください。
4. インタビューはまだ実施していないと明記してください。
5. 採用面接の質問を作らないでください。
誘導質問の例問題中立的な質問への修正
申込フォームが複雑すぎましたよね?複雑だったという結論を先に提示最近の申込過程を最初から思い出してください。読み直したり止まったりした部分はありましたか? あった場合、何を確認しようとしましたか?
項目が多すぎませんでしたか?項目数が問題だと前提化入力に時間がかかった項目や、飛ばしたいと感じた項目はありましたか?
ボタンの位置が分かりにくかったですよね?特定の原因を回答に含めている次の段階へ進むとき、何を見てどこを選択したか説明してください。
もっと簡単に変えたほうがいいですよね?改善方向を強要1か所だけ変えられるなら、どの部分を最初に変えたいですか? 理由も教えてください。

0315分に収まるインタビューの流れを作る

質問を多く作ることより、限られた時間で実際の経験を十分に聞けるよう順序を決めることが重要です。以下の例は、導入2分、経験質問8分、改善質問3分、まとめ2分で正確に15分を配分した編集例です。

結果例
[AI支援で作成・確認した編集例 — 実際のインタビュー結果ではありません]

導入 2分
1. 今日は申込過程の実際の経験を理解するためのインタビューです。正解はなく、個人情報・健康情報・所得情報をお話しいただく必要はありません。
2. 最近この申込フォームを使った状況を短く思い出してください。

経験質問 8分
3. 申込を開始してから完了するまで、どのような順序で進めましたか?
4. 途中で少し止まったり、前の段階に戻ったりした部分はありましたか? あった場合、何を確認しようとしましたか?
5. 理解しにくかった、または意味を再確認した表現はありましたか?
6. 入力を終えた後、送信前にもう一度確認した項目はありましたか?
7. 予想と違う進み方をした部分があった場合、どのようなことがありましたか?

改善質問 3分
8. 1か所だけ変えられるなら、何を最初に変えたいですか?
9. そのまま維持してほしい部分もありますか?

まとめ 2分
10. 私が尋ねていないことで、申込体験を理解するうえで重要だと思う点はありますか?

状態: インタビューはまだ実施しておらず、上記内容は質問案である。
区間時間主な目的質問番号
導入2分目的説明と最近の経験の想起1〜2
経験質問8分実際の行動・停止・再確認過程の把握3〜7
改善質問3分変更希望と維持希望の確認8〜9
まとめ2分抜けている経験の確認10
合計15分S2を満たす全体

04予想回答と実際のインタビュー証拠を分ける

質問を準備するとき、「この質問にはこのような答えが出そうだ」という予想が生まれることがあります。しかし予想回答は質問の順序を確認するための補助メモにすぎず、実際の利用者証拠ではありません。インタビュー前には、回答数、代表的な意見、繰り返し現れる不便を確定できません。

文現在使用できるか理由
利用者は送信ボタンを見つけにくいと言った。使用不可インタビューがまだ実施されていない
送信段階で混乱があるか質問する。使用可能調査する質問を表現したもの
複数の利用者が項目数を減らしてほしいと求めた。使用不可実際の回答がない
項目数が負担だったか中立的に確認する。使用可能事前の質問設計
インタビュー後、繰り返し現れる経験と例外を分けて記録する。使用可能今後の分析手順

実際のインタビューが終わった後でも、1人の回答をすべての利用者に一般化してはいけません。この記事では、インタビュー実施後の統計的代表性や標本設計は扱わず、質問案を作る段階までを扱います。

05間違った質問案を見つけたら再依頼する

AIが調査目標を早く理解しようとすると、問題をあらかじめ確定した質問を作ることがあります。機微な情報を尋ねたり、まだインタビューしていない予想回答を結果のように書いたりする場合も合わせて確認する必要があります。

誤った結果例
[誤った編集例]
1. 申込フォームが複雑で、途中でやめたくなったことがありましたよね?
2. もっと簡単な申込フォームを望みますよね?
3. 年収はいくらですか?
4. 健康上の理由で申込が難しかったことはありますか?

予想結果: ほとんどの利用者が、申込フォームが複雑で送信ボタンを見つけにくいと答えるだろう。

最初の2つの質問は望む回答を誘導し、3番目と4番目の質問はS3の禁止範囲に違反します。最後の文は実際にインタビューをしていないのに、予想内容を結果のように書いています。質問の焦点を最近の実際の行動に戻し、予想は証拠ではないことを明記する必要があります。

プロンプト
質問案を書き直してください。
- 最近の実際の申込行動を尋ねる中立的な質問に変えてください。
- 回答を先に示す表現を削除してください。
- 個人情報、健康情報、所得情報に関する質問をすべて削除してください。
- インタビューがまだ実施されていないと明記してください。
- 予想回答を実際の結果のように書かないでください。
- 導入2分 + 経験質問8分 + 改善質問3分 + まとめ2分 = 合計15分を維持してください。

06インタビュー前に読者が直接点検する

完成した質問案は、インタビュー前に人が直接読み、誘導表現、時間配分、機微な情報に関する質問がないか確認します。実際のインタビューでは、参加者が予想と異なる方向に答える場合があるため、質問順を機械的にすべて消化することよりも、S1の調査目的を維持することが重要です。以下の結果例はAI支援で作成・確認した編集例であり、実際のAI製品のインタビュー品質や効果を検証した結果ではありません。

確認リスト
[読者確認チェックリスト]
□ 目的が最近の申込過程の難しさ把握として維持されているか?
□ インタビューがまだ実施されていないと明記しているか?
□ 導入2分、経験8分、改善3分、まとめ2分で合計15分か?
□ 「不便でしたよね?」のような回答を誘導する表現がないか?
□ 最近の実際の行動を思い出させる質問が含まれているか?
□ 個人情報を尋ねていないか?
□ 健康情報を尋ねていないか?
□ 所得情報を尋ねていないか?
□ 予想回答を実際の利用者証拠として使っていないか?
□ 採用面接の質問に変わっていないか?
□ 実際のインタビュー後は、観察された回答と事前予想メモを分けて記録する準備ができているか?

自分で確認する項目

編集例の確認範囲: S1〜S3の目的・時間・禁止情報の条件、2+8+3+2分の時間合計、誘導質問の修正方法、インタビュー未実施という状態が互いに矛盾しないか確認しました。

  • インタビュー合計時間15分を確認
  • 導入2分・経験8分・改善3分・まとめ2分を保持
  • 個人情報・健康・所得に関する質問を除外
  • 誘導質問を最近の実際の行動中心の中立的な質問へ修正
  • 予想回答を実際の証拠として使用しない
  • 採用面接ではなく利用者調査として維持
検証範囲の限界

実際のインタビューを実施したり、AI製品のインタビュー生成品質・正確性・効果を検証したりしていません。質問の適切性は調査状況や参加者特性によって異なる場合があり、この例は個人情報・研究倫理・法律に関する助言の代わりにはなりません。

AIで文書の2つのバージョンを比較する：変更・追加・削除・同一を区別する

同じイベント案内のV1とV2をAIに提示し、5つの比較項目を変更・追加・削除・同一に分けて確認する実習です。削除された文を勝手に解釈せず、文書に実際に記載されている差分だけを記録する方法を学びます。

AIでお知らせからFAQを作る：原文にない答えは「要確認」のまま残す

短いお知らせ文から6つのFAQを作り、根拠がある質問にはsource IDを付け、料金・返金・キャンセル待ちのように原文にない内容は勝手に答えを作らない方法を練習します。

AIで自由記述の意見をテーマ別に整理する：複数ラベルと分類保留を扱う

6つの短い自由記述意見を決められたテーマに分類し、1つの意見に2つのテーマが含まれる場合は複数ラベルを許可する実習です。ラベル合計が回答者数を上回ることがある理由と、根拠のない満足度や感情の強さを推測しない方法も確認します。

AIで難しい利用案内をやさしい言葉に直す：条件・例外・否定・期限を保つ

架空の資料貸出案内4文を分かりやすい表現に直しながら、登録会員という条件、7日の期限、予約資料は延長不可、非予約資料は1回の延長申請が可能だが承認は確定ではないという重要条件を失わない方法を練習します。

AIで調査質問と検索計画を作る

漠然とした調査目標を事実質問・経験質問・判断質問に分け、何をどこで確認すべきか検索計画を作る実習です。AIに検索結果を作らせるのではなく、確認すべき資料と未確認項目を先に整理します。

制約条件を決めてAIでアイデアを発想する

参加人数、時間、印刷物、購入可否、使用機材などの制約条件を先に固定し、AIに互いに異なる4つの代案を発想させる実習です。どのアイデアが最も良いか決めるのではなく、各案が条件を守っているか確認し、条件が変わったときに再依頼する方法を扱います。

AIで発表練習用の質問と回答を準備する

すでに整理された架空の発表資料を基に、想定聴衆質問6つと根拠、短い回答、分からない場合の確認計画を作る実習です。発表構成の作成やAI音声評価ではなく、限られた根拠を誇張せず質問に答える練習に焦点を当てます。
