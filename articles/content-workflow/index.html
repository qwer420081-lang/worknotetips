01한 행에 글 한 편의 다음 조치 담기

글감 목록만 있으면 어느 원고가 검토 중이고 무엇이 발행을 막는지 알기 어렵습니다. 이 예제는 글ID, 독자, 결과물, 작성·검수 담당, 상태, 근거, 개인정보 점검, 승인일, 게시URL, 배포버전을 한 행으로 연결합니다. 글ID는 제목이 바뀌어도 유지해 자료를 다시 찾는 기준으로 사용합니다.

확인해 주세요

CSV의 EX-001~EX-004는 설명용 합성 샘플입니다. 승인 상태와 날짜도 예시이며 실제 승인·발행 기록이 아닙니다. CSV에는 드롭다운, 권한, 버전 기록이 들어 있지 않습니다.

02열과 상태의 뜻을 먼저 정하기

열 묶음무엇을 적는가
글ID·제목·독자·결과물어떤 문제를 누가 해결하고 무엇을 받는지
작성담당·검수담당·검수기한역할과 확인해야 할 날짜
상태·다음조치지금 단계와 다음 사람이 할 일
근거자료·개인정보점검공식 출처 또는 합성 예제 설명과 점검 결과
승인일·게시URL·배포버전승인된 시점과 실제 반영한 결과

상태는 글감, 작성중, 검수중, 수정요청, 승인, 발행, 보류 중 하나만 씁니다. “승인”은 검토를 끝냈다는 팀의 기록이고 “발행”은 사이트에 반영한 뒤 결과를 확인했다는 기록입니다. 이 구분은 Sheets 자체의 승인 시스템이 아니라 우리가 정한 운영 규칙입니다.

03CSV를 가져오고 드롭다운 설정하기

  1. 운영자가 Google Sheets에서 새 관리표를 준비하고 파일 > 가져오기에서 로컬 content-register.csv를 선택합니다. 가져오기 위치와 구분자를 확인하며 기존 운영표를 무심코 대체하지 않습니다.
  2. 가져온 뒤 제목행 14열과 샘플 4행, 한글, 빈 승인일·게시URL이 유지되는지 확인합니다. 이 글에서는 실제 Google Sheets 가져오기를 시험하지 않았습니다.
  3. 검수기한과 승인일은 날짜로 인식되는지 확인하고 YYYY-MM-DD로 표시합니다. 글ID는 텍스트 식별자로 유지합니다.
  4. 상태 열의 데이터 셀을 선택해 삽입 > 드롭다운 또는 데이터 > 데이터 확인에서 일곱 상태를 등록합니다. 한 행에는 한 상태만 선택하게 합니다.
  5. 개인정보점검 열에는 미점검, 수정필요, 완료를 등록합니다. 드롭다운의 목록 외 값 처리 설정도 확인합니다.
  6. 샘플로 동작을 확인한 뒤 합성 행을 실제 기록과 혼동하지 않게 제거하거나 별도 연습 사본에 남깁니다.

Google 공식 도움말은 파일 가져오기와 셀 드롭다운을 별도 기능으로 안내합니다. CSV는 값만 전달하므로 가져온 뒤 이 설정을 추가해야 합니다. 자동 동기화나 연결이 이미 준비된 파일이라고 표시하지 않습니다.

04필터 보기로 각자의 작업만 보기

검수 담당자는 상태가 검수중인 행을, 작성자는 자신의 수정요청 행을 먼저 보고 싶을 수 있습니다. 데스크톱 Sheets의 데이터 > 필터 보기 만들기에서 상태와 담당 기준을 선택해 “검수 대기”, “내 수정 항목”처럼 저장합니다. 일반 필터는 공유 파일의 다른 사용자에게도 보일 수 있으므로 개인별 작업 정리에는 필터 보기를 사용합니다.

  • 필터는 행을 숨기는 기능입니다. 삭제나 권한 제한으로 취급하지 않습니다.
  • 한 열만 따로 정렬하면 제목과 담당 정보가 엇갈릴 수 있으므로 관리 범위 전체를 정렬 대상으로 확인합니다.
  • 기한이 비어 있는 행도 따로 확인합니다. 필터에서 보이지 않는다고 완료된 것은 아닙니다.
  • 보기 권한으로 만든 임시 필터 보기는 저장되지 않을 수 있으므로 필요한 관리 역할과 저장 여부를 확인합니다.

05공유 권한과 버전 기록을 관리하기

파일 소유자는 일반 액세스를 제한됨으로 두고 필요한 사람을 지정하는 방식을 검토합니다. 작성 담당은 편집자, 의견만 남기는 검수자는 댓글 작성자, 읽기만 하는 관계자는 뷰어로 나눌 수 있습니다. 댓글 작성자는 셀의 상태를 직접 바꿀 수 없으므로 검수 의견을 받은 편집 담당이 상태와 승인일을 기록하도록 정합니다. 권한은 실제 업무 필요에 맞게 운영자가 부여합니다.

편집 권한이 있는 사용자는 버전 기록에서 이전 상태와 변경자를 확인하고 중요한 시점의 버전에 이름을 붙일 수 있습니다. 승인 직전의 상태를 찾는 데 도움이 되지만 사이트 파일의 버전 기록과 같지는 않습니다. 원본 복원은 다른 편집을 되돌릴 수 있으므로 영향을 확인하고 수행합니다. CSV를 내려받아도 공유 권한과 버전 기록이 함께 옮겨지는 것은 아닙니다.

06승인부터 사이트 반영까지의 수동 흐름

  1. 검수자는 출처·예제 결과·민감정보를 확인하고 수정 의견 또는 승인 의견을 남깁니다.
  2. 편집 담당은 의견을 반영한 원고를 기준으로 상태를 승인으로 바꾸고 승인일을 기록합니다.
  3. 발행 담당은 승인된 내용을 사이트의 콘텐츠 JSON과 다운로드 자산에 수동 반영합니다. 이 예제에는 Sheets에서 사이트로 보내는 자동 CMS 동기화가 없습니다.
  4. 변경된 글의 구조, 링크, 예제, 페이지 표시를 검증하고 배포합니다. 사이트의 audience가 owner-private이면 결과도 그 접근 범위에 머뭅니다.
  5. 배포한 페이지를 확인한 뒤 실제 게시URL과 배포버전을 적고 상태를 발행으로 바꿉니다. 공개 발행이 필요하면 별도로 사이트의 공개 audience 전환과 접근 확인을 진행해야 합니다.
  6. 수정이 생기면 같은 글ID를 유지한 채 수정요청 또는 검수중으로 되돌리고 변경 이유를 다음조치에 적습니다.

“Sheets에서 승인으로 바꾸면 사이트가 갱신된다”는 자동 동작은 구현되어 있지 않습니다. 이 관리표는 누가 어떤 원고를 승인하고 어느 배포에 반영했는지 사람이 연결하는 기록입니다.

07합성 샘플로 운영 규칙 확인하기

샘플상태·점검현재 필요한 조치
EX-001글감 / 미점검합성 예제 초안 작성
EX-002작성중 / 미점검인수인계 항목 보완
EX-003검수중 / 수정필요내부 경로 제거 후 재검토
EX-004승인 / 완료JSON 반영·검증·배포; 게시URL은 아직 빈칸

EX-004도 게시URL과 배포버전이 없으므로 발행 완료로 집계하지 않습니다. 반대로 링크만 넣었다고 검수를 건너뛸 수도 없습니다. 게시 전에 승인일, 근거, 개인정보 점검 결과가 모두 있는지 사람이 확인합니다. CSV에는 이런 판단을 강제하는 수식이나 자동화가 들어 있지 않습니다.

  • 같은 글ID가 두 번 있지 않은지 확인합니다.
  • 상태가 발행인 행의 실제 링크가 열리고 해당 원고인지 확인합니다.
  • 필터를 해제해 보류·미정·빈 담당이 빠지지 않았는지 봅니다.
  • 공유 목록과 일반 액세스를 함께 확인합니다.
  • 버전 기록을 볼 수 있는 역할과 댓글만 남길 역할을 시험용 사본에서 확인합니다.

08다운로드와 검증 범위

content-register.csv는 14열, 합성 자료 4행의 로컬 템플릿입니다. README.txt, column-guide.txt, workflow-checklist.txt에는 가져오기 후 설정과 상태 규칙이 있습니다. 로컬 파일의 UTF-8, 행·열 개수, 글ID 중복, 허용 상태, 샘플의 빈 게시URL을 확인했습니다. Google Sheets 실제 가져오기, 드롭다운·권한·버전 기록 조작은 시험하지 않았습니다.

계정이나 Google Drive 파일을 생성·연결하지 않았으며 사이트 checkout도 수정하지 않았습니다. 조직 계정에서는 관리 정책에 따라 공유 범위가 제한될 수 있습니다. 공식 도움말은 2026년 9월 19일 확인했으며 화면 언어·제품 갱신에 따라 메뉴 표시가 달라질 수 있습니다.
