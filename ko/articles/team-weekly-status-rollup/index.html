AI 주간 보고서: 여러 팀원의 진행 상황을 하나로 정리하기

팀원마다 형식이 다른 주간 업데이트를 AI로 모아 완료·진행·지연·의존 관계·도움 필요·확인 필요로 재구성하는 방법을 연습합니다. 하늘팀의 같은 기간 보고를 사용해, 숫자가 다를 때 한쪽을 지우지 않고 기준 시각과 출처를 함께 남기는 AI 주간 보고서 예시를 만듭니다.

01개인 보고를 붙이는 것과 팀 상태를 만드는 것은 다르다

여러 사람이 주간 업데이트를 따로 쓰면 완료, 예정, 도움 요청이 서로 다른 형식에 흩어집니다. 팀 협업 AI의 역할은 문장을 단순히 줄이는 것이 아니라, 팀이 함께 봐야 할 상태와 연결 관계를 드러내는 것입니다.

이번 예시는 하늘팀의 2026-10-19~2026-10-23 업데이트를 하나의 AI 주간 보고서로 합칩니다. 서로 다른 신청 인원 기록은 삭제하지 않고 기준 시각과 출처를 함께 남깁니다.

보고 항목합칠 때 볼 것그대로 합치면 생길 문제
완료·진행끝난 일과 계속되는 일현재 상태가 섞일 수 있음
지연원래 예정과 현재 조치지연이 묻힐 수 있음
의존 관계선행 업무가 필요한 일병목을 놓칠 수 있음
도움 필요누가 무엇을 확인할지요청이 개인 메모에 남음
충돌 보고기준 시각과 출처AI가 한쪽을 임의 선택할 수 있음

02네 사람의 업데이트와 공통 사실을 입력 자료로 묶기

공통 사실 뒤에 팀원별 원문 항목과 출처 태그를 붙입니다. 신청 인원처럼 같은 기간에 바뀔 수 있는 값은 날짜와 시각까지 적어야 갱신인지 충돌인지 검토할 수 있습니다.

입력 자료
공통 사실
- 하늘팀 4명: 민서(팀장·전체 일정), 준호(장소·물품), 서연(홍보·신청 접수), 도윤(프로그램·강사 섭외)
- 행사: 동네 디지털 기초 워크숍
- 행사 날짜: 2026-11-14
- 행사 시간: 14:00–16:00
- 정원: 30명
- 대상: 지역 주민
- 참가비: 없음
- A안 시민센터 3층 세미나실: 수용 32명, 빔프로젝터 있음, 엘리베이터 있음, 대관 가능 확인됨
- B안 구립도서관 강당: 수용 60명, 대관 가능 여부 미확인
- 장소 확정 기한: 2026-10-24
- 홍보물 최종본 기한: 2026-10-28
- 강사 확정 기한: 2026-10-30
- 신청 현황: 2026-10-23 기준 22명
- 이번 주 보고 기간: 2026-10-19~2026-10-23

민서 업데이트
[업데이트-민서-1] 2026-10-23 09:00에 서연에게 받은 신청 현황은 20명으로 메모함.
[업데이트-민서-2] 장소는 2026-10-24까지 확정해야 함. A안과 B안을 비교한 뒤 결정 필요.
[업데이트-민서-3] 홍보물 최종본은 장소명이 들어가야 하므로 장소 확정 후 마무리 가능.

준호 업데이트
[업데이트-준호-1] A안의 대관 가능 여부, 빔프로젝터, 엘리베이터를 확인했고 장소 비교 자료를 정리함.
[업데이트-준호-2] B안의 수용 인원은 60명이지만 대관 가능 여부는 아직 확인되지 않음.
[업데이트-준호-3] 물품 수량 확인을 2026-10-23에 끝낼 예정이었으나 완료하지 못함. 2026-10-26에 다시 확인 예정.

서연 업데이트
[업데이트-서연-1] 2026-10-23 16:00 기준 신청자는 22명.
[업데이트-서연-2] 홍보물 문안은 진행 중이며 최종본은 2026-10-28까지 필요함.
[업데이트-서연-3] 홍보물에 최종 장소명을 넣어야 해서 장소 확정 결과가 필요함.

도윤 업데이트
[업데이트-도윤-1] 프로그램 구성 1차안을 작성함.
[업데이트-도윤-2] 강사 섭외는 진행 중이며 확정 기한은 2026-10-30.
[업데이트-도윤-3] 준호에게 빔프로젝터 연결 방식 확인을 도와달라고 요청함.

20명과 22명은 오타로 단정할 수 없습니다. 같은 날짜의 09:00과 16:00 기록이므로 두 값을 모두 유지하고 기준 시각 차이를 표시해야 합니다.

03상태·의존·충돌을 분리해서 정리하도록 요청하기

요청문에는 완료·진행·지연·의존 관계를 나누고, 서로 다른 수치나 상태는 임의로 합치지 말라는 규칙을 넣습니다.

요청문
위 입력 자료를 바탕으로 팀 공유용 주간 보고서를 작성해줘.

규칙:
- 완료, 진행, 지연, 의존 관계, 도움 필요, 확인 필요로 나눠라.
- 각 항목 끝에 원문 출처 태그를 그대로 붙여라.
- 서로 다른 보고를 한쪽으로 합치거나 삭제하지 마라.
- 신청 인원처럼 기준 시각이 다른 값은 날짜와 시각을 함께 보여주고 왜 확인이 필요한지 설명하라.
- 입력에 없는 담당자, 날짜, 시각, 숫자, 완료 여부를 만들지 마라.
- 확인되지 않은 내용은 '확인 필요'라고 써라.
- 실제 개인정보나 연락처를 추가하지 마라.
- 마지막에 팀이 바로 확인할 항목만 짧게 정리하라.

04좋은 예시는 충돌과 의존 관계를 숨기지 않는다

다음은 실제 AI 실행 기록이 아니라 편집 예시입니다. 각 항목에 원문 출처를 남겨 팀원이 근거를 되짚을 수 있게 합니다.

예시 결과
[예시 결과 · 실제 AI 실행 결과 아님]
하늘팀 주간 상태 정리
보고 기간: 2026-10-19~2026-10-23

완료
- 준호: A안의 대관 가능 여부, 빔프로젝터, 엘리베이터 확인과 장소 비교 자료 정리를 완료함. [업데이트-준호-1]
- 도윤: 프로그램 구성 1차안을 작성함. [업데이트-도윤-1]

진행
- 서연: 홍보물 문안을 진행 중이며 최종본 기한은 2026-10-28임. [업데이트-서연-2]
- 도윤: 강사 섭외를 진행 중이며 확정 기한은 2026-10-30임. [업데이트-도윤-2]
- 민서: A안과 B안을 비교해 2026-10-24까지 장소 확정이 필요함. [업데이트-민서-2]

지연
- 준호: 2026-10-23 완료 예정이던 물품 수량 확인을 끝내지 못했고 2026-10-26에 다시 확인 예정임. [업데이트-준호-3]

의존 관계
- 서연의 홍보물 최종본은 최종 장소명이 필요해 장소 확정 결과에 의존함. [업데이트-민서-3] [업데이트-서연-3]

도움 필요
- 도윤이 준호에게 빔프로젝터 연결 방식 확인 도움을 요청함. [업데이트-도윤-3]

확인 필요
- 신청 인원 기록이 2026-10-23 09:00 기준 20명과 2026-10-23 16:00 기준 22명으로 다름. 기준 시각이 달라 갱신 과정일 수 있으므로, 공유할 때 두 출처를 함께 남겨야 함. [업데이트-민서-1] [업데이트-서연-1]
- B안은 수용 60명이지만 대관 가능 여부가 미확인 상태임. [업데이트-준호-2]

팀 확인 항목
- 민서: 장소 확정 결과 공유 필요. [업데이트-민서-2]
- 준호: 물품 수량과 빔프로젝터 연결 방식 확인 필요. [업데이트-준호-3] [업데이트-도윤-3]
- 서연: 신청 인원 기준 시각을 유지해 최신 현황 공유 필요. [업데이트-서연-1]

지연, 홍보물의 장소 의존 관계, 신청 인원의 기준 시각 차이가 따로 보입니다. 출처 태그가 있어 각 담당자가 자신의 원문과 직접 대조할 수 있습니다.

05그럴듯하지만 위험한 주간 보고를 구별하기

잘못된 결과
[잘못되기 쉬운 결과 예시 · 실제 AI 실행 결과 아님]
하늘팀은 전반적으로 계획대로 진행 중이다. 신청자는 25명으로 확정됐고 장소는 A안으로 결정됐다. 준호는 2026-10-25까지 모든 물품을 준비하고, 도윤은 강사 계약을 완료했다. 홍보물은 장소 문제가 해결되어 바로 배포할 수 있다.

이 예시는 문장이 간결하지만 원문 검토용으로는 부적절합니다. 신청자 25명은 입력에 없고, 장소도 A안으로 결정됐다는 기록이 없습니다. 준호의 새 기한과 도윤의 강사 계약 완료도 만들어낸 내용이며, 홍보물의 의존 관계까지 임의로 해소했습니다. 수정할 때는 입력에 없는 사실을 삭제하고, 미정은 확인 필요로 되돌리며, 지연과 충돌을 별도 항목으로 복원해야 합니다.

확인 목록
공유 전 사람 확인
- 각 팀원이 자신의 완료·진행 상태를 원문과 대조한다.
- 지연된 업무가 정상 진행 항목에 섞이지 않았는지 본다.
- 다른 업무 결과가 필요한 항목은 의존 관계로 표시됐는지 본다.
- 도움 요청이 빠지거나 담당자가 바뀌지 않았는지 본다.
- 충돌하는 수치에는 날짜·시각·출처가 함께 남아 있는지 본다.
- 실제 자료를 사용할 때는 조직의 정보보호 정책을 확인하고 민감정보를 AI 채팅 도구에 넣지 않는다.

06AI 초안은 팀원이 확인한 뒤 공유본이 된다

AI 주간 보고서는 여러 업데이트를 한 화면에 모으는 초안으로는 유용하지만, 어떤 보고가 최신인지 또는 지연을 어떻게 처리할지는 팀이 확인해야 합니다. 특히 숫자 변화가 정상적인 갱신인지 서로 다른 집계 기준 때문인지 AI가 원문만 보고 확정할 수 없는 경우가 있습니다. 공유 전에는 작성자별 확인을 받고, 확인되지 않은 항목은 그대로 남겨두는 편이 안전합니다.

  • 완료 여부는 해당 업무 담당자가 확인한다.
  • 기한과 의존 관계는 전체 일정을 보는 사람이 함께 확인한다.
  • 수치가 다르면 어느 기록을 지울지 먼저 결정하지 말고 기준 시각과 출처를 확인한다.
  • AI가 만든 새 해석이 원문 사실처럼 섞이지 않았는지 본다.
  • 팀 공유본에는 확인된 내용과 확인 필요 내용을 구분해 남긴다.

다음 글에서는 여러 사람의 상태를 합치는 문제에서 한 단계 더 나아가, 한 사람이 자리를 비울 때 다른 사람이 업무를 이어받을 수 있도록 만드는 「AI 업무 인수인계 문서 만들기: 흩어진 메모를 이어서 일할 수 있게 정리하기」를 다룹니다.

직접 확인할 항목

가상 입력 자료와 편집 예시 · AI 실제 실행 없음 · 이름·날짜·수치 일치 검사

  • 네 사람의 업데이트가 완료·진행·지연·의존 관계·도움 필요·확인 필요 중 적절한 위치에 반영됐는지 확인
  • 신청 인원 20명과 22명이 각각의 기준 시각 및 출처와 함께 유지되는지 확인
  • 출력의 담당자·날짜·시각·숫자가 입력 자료에 존재하는지 확인
  • 지연된 물품 수량 확인과 홍보물의 장소 의존 관계가 누락되지 않았는지 확인
  • A안과 B안의 상태를 AI가 임의로 결정하거나 확정하지 않았는지 확인
  • 효과를 나타내는 퍼센트나 배수 수치를 만들지 않았는지 확인
