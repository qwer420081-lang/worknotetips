팀 협업 AI로 흩어진 의견 비교하기: 장소 A안·B안 결정 지원

여러 팀원의 의견이 엇갈릴 때 AI가 결론을 대신 내리게 하지 않고, 확인된 사실·근거·반대 의견·미확인 가정을 같은 틀에 놓아 비교하는 방법을 연습합니다. 하늘팀의 워크숍 장소 A안과 B안을 예로 들어 결정권자와 결정 기한을 명확히 두고, 팀이 최종 판단하기 전에 확인할 항목을 남깁니다.

이런 분께팀 협업 AI를 이용해 여러 사람의 의견을 비교하되 최종 의사결정 책임과 근거 추적을 팀에 남기고 싶은 비개발자

준비사항
  • 텍스트를 입력할 수 있는 AI 채팅 도구
  • 팀원별 의견과 확인된 사실을 구분해 정리할 수 있을 것
  • 실제 기밀·고객정보 대신 가상 예제를 사용할 것
  • AI가 만든 비교 결과를 원문과 직접 대조할 것

01의견이 많을수록 먼저 사실과 선호를 분리하기

팀에서 선택지를 정할 때는 확인된 사실, 개인의 선호, 아직 검증하지 않은 가정을 분리해야 합니다. 'B안이 더 안전하다'는 의견은 수용 인원이 더 크다는 사실을 근거로 할 수 있지만, 실제로 정원을 넘는 신청이 생길지와 B안 대관이 가능한지는 별도 확인이 필요합니다. 팀 협업 AI는 이런 문장을 항목별로 나누고 출처를 붙이는 보조 도구로 쓸 수 있지만, 최종 선택은 책임자가 해야 합니다.

구분AI가 정리할 내용사람이 확인할 내용
확인된 사실수용 인원, 설비, 대관 확인 상태처럼 원문에 명시된 정보원문과 정확히 일치하는지
팀원 의견누가 어느 선택지를 선호하고 어떤 이유를 제시했는지의견을 사실처럼 바꾸지 않았는지
미확인 가정정원 초과 신청 가능성처럼 아직 확인되지 않은 전제추가 확인이 필요한지
반대 의견다수 의견과 다른 근거 또는 우려소수 의견이 빠지지 않았는지
결정 조건결정권자, 결정 기한, 결정 전 확인할 항목최종 결정이 실제로 승인되었는지

이번 가상 사례는 하늘팀이 「동네 디지털 기초 워크숍」 장소를 정하는 상황입니다. A안과 B안은 확인 수준과 팀원 선호가 다르므로, 결과를 추천 한 줄로 줄이지 않고 근거와 미확인 사항을 함께 남깁니다.

02팀원 의견과 공통 사실을 출처 태그와 함께 입력하기

아래 입력은 학습용 가상 자료입니다. 출처 태그를 각 문장 앞에 붙이면 결과에서 근거를 다시 찾기 쉽습니다. 서로 다른 의견은 합치지 않고 원문 상태로 제공합니다.

[공통-장소-2] B안: 구립도서관 강당, 수용 60명, 대관 가능 여부 미확인
[공통-일정-1] 장소 확정 기한: 2026-10-24

[메모-준호-1] 준호는 장소·물품 담당이다. A안은 수용 32명, 빔프로젝터 있음, 엘리베이터 있음, 대관 가능 확인됨이라고 정리했다.
[메모-준호-2] 준호는 B안이 수용 60명이라는 점은 확인했지만 대관 가능 여부는 아직 확인하지 못했다.
[메모-서연-1] 서연은 홍보·신청 접수 담당이다. 2026-10-23 기준 신청은 22명이며, 홍보물 최종본 기한은 2026-10-28이다.
[메모-서연-2] 서연은 장소가 2026-10-24까지 확정되어야 홍보물의 장소 표기를 안정적으로 마무리할 수 있어 A안을 선호한다.
[메모-도윤-1] 도윤은 프로그램·강사 섭외 담당이다. 정원 초과 신청 가능성에 대비해 수용 60명인 B안을 선호한다.
[메모-도윤-2] 도윤도 B안의 대관 가능 여부가 미확인이라는 점은 알고 있으며, 결정 전에 확인이 필요하다고 적었다.
[가정-1] 정원 30명을 넘는 신청이 실제로 발생할지는 현재 자료만으로 확인할 수 없다.

'B안 수용 60명'은 확인된 사실이지만 '정원 초과 신청이 생긴다'는 것은 가정입니다. A안 선호가 여러 명에게서 나와도 도윤의 B안 선호를 지우지 않아야 합니다. 요청문에서도 사실·선호·가정을 구분하도록 명시합니다.

03결론 대신 비교 구조와 확인 질문을 요청하기

요청문의 핵심은 AI에게 장소를 골라 달라고 하지 않는 것입니다. 선택지마다 확인된 근거, 반대 의견, 미확인 가정을 분리하고 출처 태그를 붙이게 합니다. 자료에 없는 담당자·기한·결정도 만들지 못하게 제한합니다.

요청문
위 가상 입력 자료만 사용해 하늘팀의 장소 A안과 B안을 비교해줘.
목표는 AI가 장소를 결정하는 것이 아니라 팀이 결정할 수 있도록 근거를 정리하는 것이다.

다음 형식으로 작성해줘.
- 선택지별 확인된 사실과 근거
- 각 선택지를 지지하는 팀원 의견과 출처 태그
- 각 선택지에 대한 반대 의견 또는 우려와 출처 태그
- 사실로 확인되지 않은 가정
- 결정 전에 확인할 항목
- 결정권자와 결정 기한

규칙:
1) 모든 이름, 날짜, 시각, 숫자는 입력에 있는 것만 사용한다.
2) 다수 의견과 다른 소수 의견도 생략하지 않는다.
3) 확인된 사실과 팀원의 선호를 구분한다.
4) 자료에 없는 담당자·기한·결정은 만들지 말고 '확인 필요'로 적는다.
5) A안 또는 B안을 최종 선택했다고 쓰지 않는다.
6) 근거마다 가능한 한 [메모-이름-번호], [공통-항목-번호], [가정-1] 출처를 붙인다.

04선택지·근거·반대 의견·미확인 가정을 함께 남기기

편집 예시
[예시 결과 · 실제 AI 실행 결과 아님]
장소 선택 비교

A안: 시민센터 3층 세미나실
- 확인된 사실: 수용 32명, 빔프로젝터 있음, 엘리베이터 있음, 대관 가능 확인됨. [공통-장소-1] [메모-준호-1]
- 지지 의견: 민서는 정원 30명을 수용할 수 있고 대관 가능이 확인된 점 때문에 A안을 우선 검토하고 싶다고 했다. [메모-민서-2]

- 반대 의견 또는 우려: 도윤은 정원 초과 신청 가능성에 대비하려면 수용 60명인 B안이 낫다는 의견이다. [메모-도윤-1]
- 미확인 가정: 정원 30명을 넘는 신청이 실제로 발생할지는 확인되지 않았다. [가정-1]

- 확인된 사실: 수용 60명, 대관 가능 여부 미확인. [공통-장소-2] [메모-준호-2]
- 지지 의견: 도윤은 정원 초과 신청 가능성에 대비해 B안을 선호한다. [메모-도윤-1]
- 반대 의견 또는 우려: B안의 대관 가능 여부는 아직 확인되지 않았다. 도윤도 결정 전에 확인이 필요하다고 적었다. [메모-도윤-2]

- 미확인 가정: 정원 30명을 넘는 신청이 발생할지 확인되지 않았다. [가정-1]

결정 전 확인할 것

- 정원 초과 신청 가능성을 실제 결정 기준으로 둘지 팀이 확인. [가정-1]
- 행사 날짜 2026-11-14, 시간 14:00–16:00, 정원 30명이라는 공통 조건을 바꾸지 않고 장소 적합성을 검토. [공통-행사-2] [공통-행사-3] [공통-행사-4]

결정권자: 민서 [메모-민서-1]
결정 기한: 2026-10-24 [공통-일정-1]
최종 선택: 아직 입력 자료에 없음. 민서가 확인 후 결정해야 함.

좋은 비교 결과는 팀이 원문으로 되돌아갈 수 있어야 합니다. A안의 운영 확정성, B안의 여유 수용 인원, B안 대관 여부와 정원 초과 가능성의 미확인 상태가 각각 구분되어야 다른 팀원도 누락이나 과장을 검토할 수 있습니다.

05AI가 다수 의견을 결론으로 바꾸거나 가정을 사실로 만들지 확인하기

AI가 선택까지 대신하면 곤란합니다. 확인되지 않은 B안 대관을 확정 사실로 바꾸거나, 팀이 승인하지 않은 결정을 민서의 결정처럼 적는 것은 원문을 왜곡합니다.

편집 예시
[잘못되기 쉬운 결과 예시 · 실제 AI 실행 결과 아님]
민서는 B안 구립도서관 강당으로 최종 결정했다. B안은 대관이 확정되어 있고 신청자가 35명까지 늘어날 예정이므로 A안보다 적합하다. 준호는 2026-10-25까지 도서관 예약을 완료하면 된다.

입력에는 민서가 B안을 최종 결정했다는 기록이 없고 B안 대관도 미확인입니다. 신청 인원 예측과 준호의 새 예약 기한도 근거가 없습니다. 수정할 때는 이런 내용을 삭제하고 B안 대관 여부와 정원 초과 가능성을 '확인 필요'로 되돌립니다.

요청문
최종 검토 체크
- A안과 B안의 수용 인원과 대관 확인 상태가 입력과 같은가?
- 민서·준호·서연·도윤의 의견이 사실과 구분되어 있는가?
- 도윤의 B안 선호처럼 소수 의견이 빠지지 않았는가?
- 정원 초과 신청 가능성을 확정 사실처럼 쓰지 않았는가?
- 최종 선택을 AI가 대신 확정하지 않았는가?
- 결정권자와 결정 기한이 입력 근거와 일치하는가?
- 실제 기밀이나 고객정보가 포함되지 않았는가?

06비교표를 공유한 뒤 팀이 결정 기록을 남기기

AI 비교 초안은 완성된 의사결정 기록이 아닙니다. 팀원은 자신의 의견과 출처를 확인하고 미확인 항목을 조사한 뒤, 민서가 최종 선택과 근거를 직접 승인해야 합니다.

  • 준호는 장소 설비와 대관 확인 상태를 원문과 대조합니다.
  • 서연은 신청 현황과 홍보 일정 설명을 확인합니다.
  • 도윤은 B안 선호 이유와 미확인 가정이 정확히 분리되었는지 확인합니다.
  • 민서는 팀원 검토 후 최종 장소와 결정 근거를 직접 승인합니다.
  • 승인 전에는 AI 초안을 확정된 팀 결정으로 공유하지 않습니다.

선택지가 정리되어도 실행 요청이 모호하면 다시 혼선이 생길 수 있습니다. 다음 글 「팀 협업 AI로 모호한 업무 요청 명확하게 만들기: 요구사항·완료 기준·확인 질문」에서는 민서의 짧은 요청을 팀이 검토 가능한 요청서로 바꾸는 방법을 다룹니다.

직접 확인할 항목

가상 입력 자료와 편집 예시 · AI 실제 실행 없음 · 이름·날짜·시각·수치 일치 및 출처 태그 검사

  • A안과 B안의 수용 인원, 설비, 대관 확인 상태가 공통 가상 사례와 일치하는지 확인
  • 도윤의 B안 선호와 정원 초과 신청 가능성이라는 미확인 가정이 누락되지 않았는지 확인

  • 효과를 퍼센트나 배수로 표현한 문장이 없는지 확인
검증 범위의 한계
