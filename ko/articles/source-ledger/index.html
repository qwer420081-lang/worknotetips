이런 분께보고서·시장 조사·과제에 사용할 공개자료를 직접 찾아 정리하는 입문자

준비사항
  • CSV를 열 수 있는 표 편집기와 웹 브라우저를 준비합니다. Python 설치는 필요하지 않습니다.
  • 다운로드한 ZIP을 풀고 source_ledger.csv, README.txt, CHECKLIST.txt를 확인합니다.
  • 동봉된 3개 레코드는 설명용 가상 자료이며 실제 통계 수치를 담지 않습니다.

01자료를 다시 찾을 수 있게 기록하기

보고서에 사용할 자료를 찾으면 그 자리에서 한 행을 기록합니다. 자료 제목, 제공기관, 상세 URL을 함께 남기면 나중에 같은 자료를 다시 열 수 있습니다. 숫자를 옮기기 전에 자료가 언제의 무엇을 어떤 단위로 설명하는지도 적습니다.

이 글의 source_ledger.csv는 자료의 맥락을 기록하는 표입니다. 숫자를 자동 수집하거나 최신 여부를 판정하는 기능은 없습니다. 실제 크롤링·API 호출·계정연동을 실시하지 않았습니다.

확인해 주세요

예시 기관·자료명·날짜는 설명용 가상 자료입니다. 원자료 URL, 실제 확인일, 이용조건 URL은 확인하지 않은 상태를 표현하기 위해 비워 두었습니다.

02세 날짜와 단위를 구분하기

항목의미예시 또는 작성 원칙
reference_date자료가 설명하는 기준일2026-03-31 (가상 예시)
published_date자료가 공개된 날2026-04-10 (가상 예시)
checked_date내가 실제로 원자료를 열어 확인한 날열람 전에는 빈칸
unit값을 세거나 재는 단위개, 명, 건, 원, 천 원 등 원문 표기

포털의 수정일이 데이터의 기준일과 같다고 가정하지 않습니다. 월간·연간 자료처럼 기간을 다룬다면 scope_definition에 시작일·종료일과 누적 여부를 덧붙입니다. 기준일이 표시되지 않으면 오늘 날짜를 대신 쓰지 말고 확인 필요로 남깁니다.

0314개 열의 역할 살펴보기

열 묶음CSV의 열무엇을 남기나
기록 구분record_id, data_kind고유 ID와 가상/실제 자료 구분
출처source_title, publisher, source_url원문 제목·제공기관·상세 URL
날짜reference_date, published_date, checked_date기준일·게시일·실제 확인일
해석unit, scope_definition단위·대상·지역·집계 정의
이용조건license_url, license_note해당 자료의 이용조건 위치와 확인 내용
진행 상태verification_status, follow_up확인상태와 다음 확인 항목

source_url에는 검색 결과 주소보다 해당 자료의 상세 페이지를 넣습니다. license_url에는 실제로 적용되는 조건을 확인한 위치를 기록합니다. 파일을 내려받았다면 파일명·버전도 scope_definition이나 follow_up에 함께 적습니다.

04템플릿으로 한 건 기록하기

  1. ZIP을 풀고 source_ledger.csv를 복사해 작업용 파일을 만듭니다. 원본 템플릿은 보관합니다.
  2. CSV 가져오기에서 UTF-8을 선택하고 ID·날짜·URL 열을 텍스트로 가져옵니다. 이 파일은 표 너비나 색을 저장하지 않습니다.
  3. 가상 예시 3행을 확인한 뒤 실제 자료용 행을 추가합니다. record_id를 R001처럼 겹치지 않게 정하고 data_kind를 실제 자료로 적습니다.
  4. 원자료를 직접 열어 제목과 제공기관을 확인하고 상세 URL을 복사합니다. 이어 기준일·게시일·실제 확인일·단위·집계 범위를 적습니다.
  5. 해당 자료의 이용허락 범위와 필요한 출처 표시를 확인하고 license_url과 license_note에 남깁니다. 공공데이터포털 이용정책과 공공누리 유형안내는 글 아래 공식 참고 링크에서 확인할 수 있습니다.
  6. 모르는 항목은 비워 두고 확인상태와 다음 확인할 일을 적습니다. 작업 파일을 다른 이름의 UTF-8 CSV로 저장한 뒤 다시 열어 확인합니다.

공공데이터포털의 데이터 상세 화면에는 제공기관·수정일·이용허락범위 등의 항목이 표시됩니다. 화면의 항목 이름을 그대로 구분해 읽는 연습에 참고 문서의 실제 상세 페이지를 활용할 수 있습니다. 그 페이지는 가상 예시의 원자료가 아닙니다.

05동봉된 예시가 나타내는 상태

ID가상 자료비워 둔 핵심 항목확인상태
EX001가상 지역 A 시설 현황원자료 URL·확인일·이용조건 URL원자료 미확인
EX002가상 지역 B 접수 현황공통 미확인 항목 + 기준일기준일 확인 필요
EX003가상 지역 C 이용 현황공통 미확인 항목 + 단위단위 확인 필요

예시 3행은 어느 것도 기록 확인 완료가 아닙니다. 빈칸은 0이나 해당 없음이 아니라 확인하지 못했다는 뜻입니다. 실제 통계값 열을 만들지 않았으므로 예시를 숫자 근거로 인용할 수 없습니다.

최종 작업 결과는 자동 보고서가 아니라, 원자료를 다시 찾고 남은 확인 항목을 추적할 수 있는 출처 목록입니다.

06보고서에 사용하기 전 체크리스트

  • URL을 직접 열어 기록한 제목·기관과 같은 자료인지 확인합니다.
  • 기준일·게시일·실제 확인일이 각자 올바른 칸에 들어갔는지 확인합니다.
  • 명과 건, 원과 천 원, 당월과 누적처럼 다른 단위·범위를 한 값처럼 비교하지 않았는지 확인합니다.
  • 해당 자료의 이용조건과 출처 표시 내용을 확인했는지 검토합니다.
  • 고유 ID가 겹치지 않는지, 설명용 가상 자료가 실제 인용 대상에 섞이지 않았는지 확인합니다.
  • 원자료 URL·세 날짜·단위·정의·이용조건을 실제로 검토한 행만 기록 확인 완료로 바꿉니다. 확인할 수 없는 항목이 남으면 다른 상태를 유지합니다.

다운로드의 CHECKLIST.txt에도 같은 확인 절차와 권장 상태값을 담았습니다. 기록 확인 완료는 작업 상태이며 자료의 정확성·최신성 또는 모든 이용목적에 대한 허락을 보증하는 표시는 아닙니다.

07자주 생기는 기록 오류

문제바로잡는 방법
출처에 포털 이름만 있음원문 제목·제공기관·상세 URL을 함께 남깁니다.
기준일을 확인일로 덮어씀기준일은 자료의 시점으로 되돌리고 실제 열람일을 checked_date에 넣습니다.
수정일만 보이는데 게시일로 기록함published_date를 추측하지 않고 follow_up에 수정일만 확인했다고 적습니다.
천 원을 원으로 옮김원문 단위를 유지하고 변환이 필요하면 별도의 계산 근거를 남깁니다.
빈칸을 0으로 채움확인하지 못한 값은 빈칸과 확인 필요 상태로 표현합니다.
CSV의 날짜·한글이 바뀜가져오기에서 UTF-8과 텍스트 열을 선택하고 저장 후 다시 엽니다.

08수동 목록으로 남는 한계

  • CSV에는 자동 입력 검증이나 변경 이력이 없습니다. 상태값을 적는 것만으로 확인이 수행되지는 않습니다.
  • 자료의 변경·철회·링크 이동을 자동 감지하지 않습니다. 사용 시점에 원자료를 다시 확인해야 합니다.
  • 같은 단위와 기준일이어도 조사 대상이나 집계 정의가 다를 수 있습니다. 비교 가능성은 원문 설명을 읽고 따로 판단해야 합니다.
  • 이 글은 출처 기록 방법을 설명합니다. 실제 통계를 수집·검증하거나 이용조건에 대한 개별 법률 판단을 수행하지 않았습니다.

실행·검증 기록

Windows 11 (10.0.26200), CPython 3.12.14의 csv·json·datetime 표준 라이브러리로 템플릿 구조를 검사했습니다. 사용자는 Python 없이 CSV를 편집할 수 있습니다.

  • CSV 14열·가상 레코드 3행·고유 ID·날짜 형식 검사
  • 가상 자료 표시, 미확인 URL/확인일의 빈칸, 상태와 누락 항목의 일치 검사
  • README·체크리스트·본문의 파일명과 열 이름 일치 검사
  • 공식 이용정책·유형안내·메타데이터 화면 링크를 웹에서 확인
검증 범위의 한계
  • 실제 크롤링·계정연동·API 호출·데이터 다운로드를 실시하지 않았습니다.
  • 실제 통계 수치, 링크의 장기 유효성, Excel 앱의 CSV 표시를 검증하지 않았습니다.
