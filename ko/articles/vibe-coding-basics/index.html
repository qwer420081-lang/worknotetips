바이브코딩이란? AI에게 코드를 맡길 때 사람이 해야 할 일

바이브코딩을 단순히 '말로 시키면 AI가 알아서 만드는 것'으로 받아들이지 않고, 사람이 요구사항과 확인 기준을 정한 뒤 AI가 만든 결과를 점검하는 작업 방식으로 이해합니다. 가상의 가계부 CSV 합계 도구를 예로 들어 입력·출력·하지 말 것·확인 방법을 한 쪽 메모로 정리합니다.

이런 분께코딩 경험이 많지 않지만 Claude Code 같은 터미널형 AI 코딩 도구를 이용해 작은 자동화부터 안전하게 시작하려는 일반 사용자

준비사항
  • 생성형 AI가 답을 만들 수 있지만 틀린 내용도 만들 수 있다는 기본 이해
  • 명령어를 직접 실행하기 전에 무엇을 바꾸는지 확인하려는 습관
  • 실제 개인정보가 아닌 가상 데이터로 연습할 것

01바이브코딩을 '자동 완성'이 아니라 협업 방식으로 보기

이 시리즈에서 말하는 바이브코딩은 자연어로 원하는 작업을 설명하고, AI가 파일을 읽거나 코드를 만들고 수정하도록 도운 뒤, 사람이 결과를 확인하는 흐름을 뜻합니다. 핵심은 사람이 코드를 한 줄도 직접 쓰지 않아도 된다는 약속이 아닙니다. 오히려 무엇을 만들지, 입력과 출력이 무엇인지, 어디까지 허용할지, 결과가 맞는지 어떻게 확인할지를 사람이 먼저 정해야 합니다. 생성형 AI 기초 글 「생성형 AI란? 답변 원리와 환각을 이해하고 활용하기」에서 다룬 것처럼 AI의 답은 그럴듯해 보여도 사실이나 의도와 어긋날 수 있으므로, 코딩에서도 '생성'과 '검증'을 분리해서 생각하는 편이 안전합니다.

역할AI에게 맡길 수 있는 일사람이 직접 결정·확인할 일
요구 이해요청문을 바탕으로 작업 범위 정리목적·입력·출력·금지사항이 빠졌는지 확인
코드 작성필요한 파일과 코드 초안 작성원하지 않은 파일 변경이나 범위 확대 여부 확인
실행 준비실행 명령이나 필요한 순서 제안명령이 현재 폴더와 파일에 어떤 영향을 주는지 확인
결과 확인예상 결과와 비교 방법 제안실제 출력이 기준값과 일치하는지 직접 확인

즉, 바이브코딩의 품질은 프롬프트를 멋지게 쓰는 능력만으로 결정되지 않습니다. 작업을 작게 정의하고, AI가 한 일을 눈으로 확인할 수 있게 만들며, 틀렸을 때 어디서부터 다시 볼지 기준을 남기는 것이 더 중요합니다.

028편 동안 이어갈 가상 가계부 예제 정하기

이 시리즈는 하나의 작은 예제를 계속 확장합니다. 입력 파일은 UTF-8 CSV인 expenses.csv이고 열 이름은 date, category, amount입니다. category 값도 food, transport, supplies처럼 영어를 그대로 사용합니다. 실제 카드 사용 내역이나 개인 소비 기록은 사용하지 않고 아래처럼 가상 데이터만 사용합니다.

요청문
date,category,amount
2026-09-01,food,12000
2026-09-03,transport,1450
2026-09-03,food,8500
2026-09-10,supplies,3200
2026-09-15,transport,1450
2026-10-02,food,9800

첫 번째 목표는 이 파일을 읽어 월별 합계를 출력하는 summarize.py를 만드는 것입니다. 기대값은 2026-09가 26600, 2026-10이 9800입니다. 이후 글에서는 2026-09의 분류별 합계 food 20500, transport 2900, supplies 3200까지 확장하지만, 지금 단계에서는 아직 코드를 만들지 않습니다. 먼저 요구사항을 사람이 고정하는 연습을 합니다.

03입력·출력·하지 말 것·확인 방법을 네 칸으로 쓰기

AI에게 바로 '가계부 프로그램 만들어줘'라고 요청하면 파일 형식, 출력 모양, 라이브러리 선택, 오류 처리 범위를 AI가 임의로 채울 수 있습니다. 작은 도구라도 네 가지를 먼저 적으면 이후 대화가 훨씬 명확해집니다. 첫째 입력은 어떤 파일인지, 둘째 출력은 어떤 값이어야 하는지, 셋째 하지 말 것은 무엇인지, 넷째 사람이 무엇과 대조할지를 적습니다.

요청문
도구 이름: 가계부 CSV 월별 합계

입력
- UTF-8 CSV 파일 expenses.csv
- 열: date, category, amount
- date 형식: YYYY-MM-DD
- amount는 정수

출력
- 월별 합계를 월과 함께 표시
- 2026-09 = 26600
- 2026-10 = 9800

하지 말 것
- 실제 개인정보나 실제 결제 데이터를 사용하지 않기
- 외부 패키지를 추가하지 않기
- 입력 CSV를 수정하지 않기

확인 방법
- python summarize.py expenses.csv 로 실행
- 출력의 두 월 합계가 위 기대값과 정확히 같은지 대조

이 메모는 코드가 아닙니다. 그러나 앞으로 AI가 제안한 구현이 요구사항을 벗어났는지 판별하는 기준이 됩니다. 예를 들어 AI가 pandas를 설치하자고 제안하면 'Python 표준 라이브러리만 사용'이라는 조건과 충돌하므로 그대로 진행하지 않아도 됩니다.

04요청문에는 정답을 맞힐 수 있는 기준까지 넣기

다음 단계에서 Claude Code에 작업을 맡길 때는 요구사항 메모를 그대로 전달하거나 핵심을 요약해 사용할 수 있습니다. 좋은 요청문은 '무엇을 만들어줘'로 끝나지 않고, 입력 예시와 기대 출력, 제약, 수정 전에 확인할 사항까지 포함합니다. 이렇게 하면 AI가 만든 코드가 맞는지 사람이 판단할 근거가 남습니다.

요청문
expenses.csv를 읽어 월별 amount 합계를 출력하는 Python 스크립트를 만들 계획을 세워줘.
아직 파일은 수정하지 마.
입력 열은 date, category, amount이고 date는 YYYY-MM-DD, amount는 정수야.
Python 표준 라이브러리만 사용해야 해.
기대값은 2026-09 = 26600, 2026-10 = 9800이야.
먼저 어떤 파일을 읽고 무엇을 확인한 뒤 어떤 순서로 구현할지 설명해줘.

이 요청은 아직 코드를 작성하라고 승인하지 않습니다. '먼저 이해하고 계획하기'를 넣어 범위를 확인할 수 있게 했습니다. Claude Code 공식 문서에서도 복잡한 작업은 단계로 나누고, 바꾸기 전에 먼저 코드를 이해하게 하는 방식을 권장합니다.

05사람이 멈춰서 확인해야 하는 지점을 정하기

AI 코딩 도구는 파일을 읽고 수정하거나 명령 실행을 제안할 수 있으므로, 초보자에게는 '언제 Yes를 누를지'보다 '언제 멈춰서 볼지'가 중요합니다. 특히 처음 보는 명령, 여러 파일을 한꺼번에 바꾸는 제안, 요구하지 않은 패키지 설치, 입력 원본을 수정하는 코드가 나오면 다음 단계로 넘기기 전에 이유를 확인합니다.

  • 요청한 폴더 안의 파일만 대상으로 하는지 확인한다.
  • 입력 CSV를 읽기만 하고 덮어쓰지 않는지 확인한다.
  • 표준 라이브러리만 사용한다는 제약을 지키는지 확인한다.
  • 기대값 26600과 9800을 비교할 수 있는 출력 형태인지 확인한다.
  • 명령 실행이나 파일 수정 전 무엇이 바뀌는지 설명을 요구한다.

코드 검토 체크리스트나 단위 테스트 자체는 기존 Worknote 글에서 별도로 다루고 있으므로 여기서는 반복하지 않습니다. 이번 시리즈의 초점은 터미널형 AI 코딩 도구와 협업할 때 작업 범위와 변경 시점을 사람이 통제하는 흐름입니다.

06첫 글의 결과물: 한 쪽 요구사항 메모 완성하기

이 글을 끝냈다면 아직 Claude Code를 설치하거나 코드를 생성하지 않아도 됩니다. 대신 한 쪽 요구사항 메모가 완성되어 있어야 합니다. 다음 글에서는 이 메모를 들고 Claude Code를 설치한 뒤, 코드를 바꾸기 전에 연습 폴더를 읽고 설명하는 질문부터 시작합니다.

확인 항목이번 예제의 기준완료 판단
입력expenses.csv / date, category, amount파일과 열 이름이 명확함
출력2026-09 = 26600, 2026-10 = 9800기대값이 숫자로 고정됨
제약표준 라이브러리만 사용, 원본 CSV 수정 금지AI가 임의로 범위를 넓히기 어려움
확인python summarize.py expenses.csv 실행 후 기대값 대조사람이 직접 맞고 틀림을 판단할 수 있음

이 기준이 있으면 이후 AI가 코드를 길게 설명하더라도 핵심 질문은 단순해집니다. '내가 정한 입력을 읽는가, 내가 정한 출력을 만드는가, 하지 말라고 한 일을 하지 않는가, 그리고 내가 결과를 확인할 수 있는가'를 차례로 보면 됩니다.

직접 확인할 항목
