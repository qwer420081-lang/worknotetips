01설치 전에 계정과 연습 범위를 먼저 확인하기

Claude Code는 무료 사용을 전제로 설명하면 안 됩니다. 이 글의 기준이 된 공식 문서에서는 Claude Pro·Max·Team·Enterprise 구독, Claude Console의 API 선불 크레딧, 또는 지원되는 클라우드 제공자를 계정 경로로 안내합니다. 어떤 방식이 자신의 계정에 해당하는지는 설치 전에 공식 문서와 실제 계정 화면에서 확인합니다. 이 글은 가격이나 특정 버전 번호를 임의로 적지 않습니다.

준비 항목확인할 내용이 글에서의 선택
계정지원되는 Claude 구독·Console·클라우드 제공자 중 해당 경로무료라고 가정하지 않음

네이티브 Windows에서는 Git for Windows 설치가 권장됩니다. Git for Windows가 없으면 Claude Code가 PowerShell을 셸 도구로 사용할 수 있습니다. Git 사용법 자체는 6편에서 다루므로 이번에는 설치 환경과 첫 세션에만 집중합니다.

02운영체제에 맞는 공식 설치 명령 사용하기

권장 네이티브 설치 명령은 운영체제마다 다릅니다. 아래 명령을 복사할 때는 자신이 쓰는 셸과 운영체제를 먼저 확인합니다. 네이티브 설치는 백그라운드 자동 업데이트를 사용하지만, Homebrew와 WinGet 설치는 자동 업데이트되지 않는다고 공식 문서에 안내되어 있습니다.

요청문
# macOS · Linux · WSL
curl -fsSL https://claude.ai/install.sh | bash
요청문
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
요청문
Windows CMD:
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Homebrew:
brew install --cask claude-code

WinGet:
winget install Anthropic.ClaudeCode

설치 명령은 공식 문서에 확인된 형태를 그대로 사용하고, 인터넷에서 임의로 변형된 설치 스크립트를 섞지 않는 편이 좋습니다. 설치 방식별 최신 요구사항이나 지원 환경이 바뀌었는지는 실행 전에 공식 문서에서 다시 확인합니다.

03버전을 확인하되 특정 번호를 기대값으로 만들지 않기

설치가 끝나면 터미널을 새로 열고 `claude --version`으로 확인합니다. 공식 문서 기준으로 버전 번호와 '(Claude Code)'가 출력됩니다. 버전 번호는 시점에 따라 달라질 수 있으므로 이 글에서는 특정 숫자를 적지 않습니다.

요청문
claude --version

명령을 찾을 수 없다는 메시지가 나온다면 임의로 경로를 추측하기보다 설치 단계와 공식 문서의 문제 해결 안내를 다시 확인합니다. 이 원고에서는 실제 Claude Code를 실행하지 않았으므로 특정 오류 화면이나 성공 화면을 재현했다고 쓰지 않습니다.

04실제 프로젝트 대신 분리된 연습 폴더 만들기

첫 실행을 바로 연구 폴더나 업무 저장소에서 하지 않고, 빈 연습 폴더를 만드는 편이 안전합니다. 여기서는 vibe-expenses라는 폴더와 가상 expenses.csv만 사용합니다. 폴더를 만든 뒤 앞 글에서 정한 CSV 내용을 저장합니다.

요청문

cd vibe-expenses

파일은 UTF-8로 저장합니다. 이 단계에서는 summarize.py를 만들지 않습니다. 첫 세션의 목적은 'AI에게 바로 코딩시키기'가 아니라 현재 폴더를 읽고 설명하게 한 뒤, 사용자가 무엇을 바꿀지 결정하는 연습입니다.

05plan 모드로 시작하고 처음 로그인하기

Claude Code는 프로젝트 폴더에서 `claude`로 시작할 수 있고, 처음 실행하면 브라우저 로그인을 진행합니다. 다만 초보자는 처음부터 수정이 가능한 흐름보다 plan 모드로 시작하는 것을 권장합니다. plan 모드는 읽기 중심으로 분석과 계획을 검토하기 위한 권한 모드이며, 명령줄에서는 다음처럼 시작할 수 있습니다.

요청문
claude --permission-mode plan

처음 실행에서는 브라우저 로그인 절차가 나타날 수 있습니다. 계정을 바꾸어야 할 때는 세션 안에서 `/login`을 사용할 수 있습니다. 권한 모드는 계정과 환경에 따라 기본값이 다를 수 있으므로, 이 글은 '항상 기본이 Manual'이라고 단정하지 않습니다. 공식 문서(2026-09-22 확인) 기준으로 Pro·Max·Team 요금제의 대화형 터미널 기본 시작 모드는 auto이고, 다른 요금제는 Manual입니다.

첫 실행에서는 브라우저 로그인이나 권한 관련 안내가 표시될 수 있습니다. 실제 화면 문구와 순서는 설치 시점과 계정에 따라 달라질 수 있으므로, 현재 화면과 공식 문서를 기준으로 확인하세요.

06파일을 바꾸기 전에 읽기 전용 질문 세 개 해 보기

세션이 시작되면 바로 '프로그램을 만들어줘'라고 하지 않고, 현재 폴더를 얼마나 정확히 이해하는지부터 확인합니다. Claude Code는 필요한 파일을 스스로 읽을 수 있고, 파일 수정이나 명령 실행 전에 승인을 요청할 수 있습니다. 이번 연습에서는 수정 요청을 하지 않고 질문만 합니다.

요청문
이 폴더에 어떤 파일이 있는지 알려줘. 파일은 수정하지 마.

expenses.csv의 열 이름과 각 열이 어떤 의미로 보이는지 설명해줘. 파일은 수정하지 마.

이 CSV로 월별 amount 합계를 계산하는 도구를 만든다면, 구현 전에 확인해야 할 사항을 세 가지로 정리해줘. 아직 코드를 만들지 마.

답변에서는 최소한 현재 파일 이름과 CSV 열을 잘못 읽지 않았는지 확인합니다. AI가 없는 파일을 언급하거나 원하지 않은 수정·설치를 제안한다면 그 이유부터 묻습니다. 실제 Claude Code가 어떤 문장으로 답하는지는 모델과 시점에 따라 달라지므로, 이 글에서는 가상의 정답 대화를 만들어 실제 출력처럼 제시하지 않습니다.

CSV 열은 무엇인가date, category, amount를 정확히 읽는가열 이름을 추측하면 원본과 대조

07종료하고 다음 글로 넘어가기

첫 세션의 목표를 달성했다면 코드를 만들지 않은 상태에서 종료합니다. 세션에서는 `/exit`을 사용할 수 있고, Ctrl+D를 두 번 눌러 종료할 수도 있습니다. `/help`로 명령 목록을 볼 수 있으며, `/clear`, `/resume`, `/compact`, `/rewind` 같은 명령도 있지만 이번 글에서는 기능 이름만 확인하고 실제 작업은 확장하지 않습니다.

요청문
/exit
  • claude --version으로 설치 확인을 마쳤다.
  • 실제 업무 폴더가 아닌 vibe-expenses 연습 폴더를 사용했다.
  • expenses.csv는 가상 데이터만 포함한다.
  • plan 모드에서 파일 수정 없이 질문 세 개를 했다.
  • 실제 코드 생성은 다음 글로 미뤘다.

다음 글에서는 앞서 만든 요구사항과 이 연습 폴더를 사용해 summarize.py를 실제로 만드는 흐름을 다룹니다. 그때는 입력 예시, 기대 출력, 표준 라이브러리만 사용한다는 제약을 한 요청문에 넣고, 생성된 Python 코드를 별도로 실행해 결과를 검증합니다.

직접 확인할 항목

Claude Code 공식 문서(2026-09-22 확인)를 기준으로 작성 · Claude Code 실제 실행 없음 · Python 실행 코드 없음

  • macOS·Linux·WSL, Windows PowerShell, Windows CMD의 네이티브 설치 명령이 공식 문서와 일치하는지 확인
  • Homebrew와 WinGet 대체 설치 명령 및 자동 업데이트 차이를 공식 문서와 대조
  • claude --version, claude --permission-mode plan, /login, /exit 명령 표기가 공식 문서와 일치하는지 확인
  • 무료 사용 가능이라고 단정하지 않고 지원 계정 경로만 제시했는지 확인
  • Claude Code 화면·응답에 해당하는 편집 예시가 '[편집 예시 · 실제 응답 아님]'으로 시작하는지 확인
  • Python 실행 코드가 포함되지 않아 Python 결과 검증을 수행했다고 잘못 주장하지 않았는지 확인

이미 동작하는 가계부 월별 합계 도구에 `--by-category` 옵션을 추가하는 과정을 예로 들어, Claude Code의 plan 모드에서 먼저 변경 계획을 검토하는 방법을 익힙니다. 구현 전에 수정 범위와 출력 형식을 고정하고, 승인 후 완성 코드를 실행해 기존 월별 합계와 분류별 합계를 함께 확인합니다.

git으로 AI가 바꾼 내용 확인하기: 작업 전 커밋부터 diff와 커밋까지

Claude Code가 파일을 수정하기 전에 git으로 기준점을 남기고, 작업 뒤에는 `git status`와 `git diff`로 실제 변경 내용을 읽는 흐름을 익힙니다. AI에게 diff 설명을 요청할 수 있지만, 설명만 믿지 않고 사람이 diff와 실행 결과를 확인한 뒤 직접 스테이징하고 커밋하는 절차를 사용합니다.

Claude Code로 에러 고치기: 재현 → 원인 → 최소 수정 → 재실행
