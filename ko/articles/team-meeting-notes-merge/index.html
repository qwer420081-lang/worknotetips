AI 회의록: 여러 참석자 메모를 합쳐 결정·할 일·미정 사항 정리하기

AI 회의록을 만들 때 한 사람의 메모만 다듬는 대신 여러 참석자의 기록을 함께 넣고, 결정·할 일·미정·기록 차이를 출처 태그와 함께 정리하는 방법을 연습합니다. 하늘팀의 2026-10-20 가상 회의 메모를 사용해 서로 다른 표현을 억지로 하나로 합치지 않고 팀 공유용 초안을 만드는 과정을 보여줍니다.

  • AI 정리본을 원문 메모와 다시 대조할 사람이 있을 것

01여러 메모를 합칠 때 출처를 지우지 않기

회의가 끝나면 참석자마다 적어 둔 내용의 초점이 다릅니다. 누군가는 결정만 적고, 다른 사람은 본인 할 일이나 아직 확인되지 않은 표현을 남깁니다. AI 회의록에서 중요한 것은 문장을 매끈하게 합치는 것보다 어떤 내용이 어느 메모에서 왔는지 추적할 수 있게 유지하는 것입니다.

이 글은 2026-10-20에 열린 가상 하늘팀 회의를 예로 사용합니다. 회의록의 목적은 입력에 없는 결정을 만드는 것이 아니라, 공통으로 확인된 사실과 담당 업무, 미정 사항, 기록 차이를 구분해 팀이 다시 확인할 수 있는 초안을 만드는 것입니다.

02참석자별 메모를 항목 번호와 함께 입력하기

입력 자료에는 참석자 이름과 항목 번호를 붙입니다. 같은 내용처럼 보여도 표현이 다르면 그대로 남겨 둡니다. 여기서는 홍보물 기한을 한 메모는 정확한 날짜로, 다른 메모는 상대적인 표현으로 적은 사례를 포함합니다.

입력 자료

회의 날짜: 2026-10-20
팀 구성: 민서(팀장·전체 일정), 준호(장소·물품), 서연(홍보·신청 접수), 도윤(프로그램·강사 섭외)

[메모-서연-2] 장소가 확정되면 홍보물의 장소 문구를 반영해야 함.

공통 신청 현황은 시리즈 배경을 맞추기 위해 별도로 적었지만, 2026-10-20 회의 메모 자체에는 그 이후 시점의 신청 인원을 결정 사항처럼 끌어오지 않습니다. 입력의 시간 범위를 구분하는 것도 회의록 검토에서 중요한 부분입니다.

03결정·할 일·미정·기록 차이를 분리해 요청하기

요청문에서는 단순 요약보다 분류 기준을 구체적으로 지정합니다. 특히 서로 다른 기록이 있을 때 더 그럴듯한 문장을 골라 확정하지 말고, 두 출처를 모두 남기게 합니다. 담당자와 기한도 입력에 근거가 없으면 '미정' 또는 '확인 필요'로 두도록 요청합니다.

요청문
위 참석자별 회의 메모를 하나의 팀 공유용 AI 회의록 초안으로 정리해줘.

분류:
- 결정 또는 재확인된 사실
- 할 일: 담당자와 기한이 입력에 있을 때만 표시
- 미정 또는 확인 필요
- 서로 다른 기록 또는 표현 차이
- 팀 공유 메시지 초안

규칙:
- 각 항목 끝에 근거가 된 원문 태그를 그대로 붙인다.
- 서로 다른 기록은 한쪽을 임의로 삭제하거나 확정하지 않는다.
- 공통 일정표와 참석자 메모를 구분해서 사용한다.
- 입력에 없는 담당자, 기한, 완료 상태를 만들지 않는다.
- 회의 이후 기준 정보는 회의 당시 결정처럼 쓰지 않는다.
- 실제 연락처나 개인정보를 추가하지 않는다.

05미정과 기록 차이를 지운 회의록은 다시 고치기

장소 관련 논의는 모두 정리되었고 홍보물 일정도 이견 없이 합의되었습니다. 각 담당자는 기존 계획대로 진행하면 되며, 별도로 확인할 사항은 없습니다.

이 예시는 입력에 남아 있는 미정 상태와 기록 차이를 지웠습니다. 최종 장소는 아직 결정되지 않았고 B안의 대관 가능 여부도 확인되지 않았습니다. 또한 준호의 '다음 주 중' 기록과 서연의 정확한 날짜 기록은 표현이 다릅니다. 이를 없애면 나중에 누가 어떤 근거로 일정을 이해했는지 추적하기 어렵습니다. 수정할 때는 미정·확인 필요 항목과 두 출처 태그를 복원해야 합니다.

06공유 전에는 원문·시점·책임자를 사람이 확인하기

팀 공유 전에 참석자 중 한 명이 정리본을 읽는 것만으로는 충분하지 않을 수 있습니다. 원문 항목이 빠지지 않았는지, 담당자와 기한이 실제 메모에 있는지, 회의 이후에 생긴 정보를 당시 결정처럼 섞지 않았는지 확인해야 합니다. 중요한 결정은 회의록 문장 자체가 아니라 팀의 승인 절차를 거쳐 확정합니다.

확인 목록
공유 전 확인 목록
- 결정·할 일·미정·기록 차이가 서로 구분되어 있는가?
- 각 핵심 항목에 원문 메모 태그가 남아 있는가?
- 담당자와 기한이 실제 입력에 있는 정보인가?
- 서로 다른 기록을 임의로 하나로 합치지 않았는가?
- 회의 이후의 상태를 회의 당시 결정처럼 쓰지 않았는가?
- 실제 기밀·고객정보·연락처가 포함되지 않았는가?

여러 사람의 메모를 합치는 다음 단계는 여러 사람의 진행 상황을 같은 기준으로 모으는 것입니다. 다음 글인 「AI 주간 보고서: 여러 팀원의 진행 상황을 하나로 정리하기」에서는 완료·진행·지연·의존 관계·도움 요청·확인 필요를 한 보고서로 묶는 방법을 다룹니다.

직접 확인할 항목

가상 입력 자료와 편집 예시 · AI 실제 실행 없음 · 이름·날짜·수치 일치 검사

  • 모든 code 블록에 role이 있고 input·prompt·output·bad_output·checklist 중 하나인지 확인
  • output의 사람 이름·YYYY-MM-DD 날짜·HH:MM 시각·숫자가 같은 글 input에 존재하는지 대조
  • 2026-10-20 회의 메모와 2026-10-23 기준 신청 현황의 시점을 혼동하지 않았는지 확인
  • 2026-11-14, 14:00–16:00, 정원 30명과 주요 기한이 공통 가상 사례와 일치하는지 확인
  • 기록 차이와 미정 사항에 출처 태그가 남아 있는지 확인
  • 표의 모든 행이 헤더와 같은 열 개수를 가지며 효과 수치 표현이 없는지 확인
검증 범위의 한계

실제 AI 도구가 생성한 회의록이 아니라 가상 메모를 바탕으로 만든 편집 예시입니다. 실제 회의에서는 참석자별 원문과 최신 상태를 사람이 대조하고, 팀의 결정·승인 절차를 별도로 따라야 합니다.

AI 업무 인수인계 문서 만들기: 흩어진 메모를 이어서 일할 수 있게 정리하기

팀 협업 AI로 흩어진 의견 비교하기: 장소 A안·B안 결정 지원

여러 팀원의 의견이 엇갈릴 때 AI가 결론을 대신 내리게 하지 않고, 확인된 사실·근거·반대 의견·미확인 가정을 같은 틀에 놓아 비교하는 방법을 연습합니다. 하늘팀의 워크숍 장소 A안과 B안을 예로 들어 결정권자와 결정 기한을 명확히 두고, 팀이 최종 판단하기 전에 확인할 항목을 남깁니다.

팀 협업 AI로 모호한 업무 요청 명확하게 만들기: 요구사항·완료 기준·확인 질문

팀 협업 AI를 개인별 요청문이 아니라 공동으로 검토하고 고치는 팀 자산으로 만드는 방법을 다룹니다. 하늘팀의 AI 회의록 정리 요청문을 v1.0에서 v1.1로 개선하고, 같은 테스트 입력으로 다시 확인하는 과정을 따라갑니다.
