AI로 공지문에서 FAQ 만들기: 원문에 없는 답은 확인 필요로 남기기

짧은 공지문을 바탕으로 여섯 개 FAQ를 만들면서, 근거가 있는 질문에는 source ID를 붙이고 요금·환불·대기처럼 원문에 없는 내용은 임의의 답을 만들지 않는 방법을 연습합니다.

이런 분께행사·교육·모임 공지에서 자주 묻는 질문을 정리하고 싶지만 AI가 원문 밖의 답까지 만들어 낼까 걱정되는 초보 일반인

준비사항
  • 공지문을 문장 단위로 나눌 수 있으면 됩니다.
  • 각 문장 앞에 S1, S2처럼 source ID를 붙여 사용합니다.
  • 실제 개인정보나 실제 기관 자료를 입력할 필요가 없습니다.

01공지문을 source ID가 있는 사실 목록으로 만들기

FAQ를 만들기 전에 공지문에서 확인 가능한 사실을 분리합니다. 이 실습의 행사는 모두 가상이며 S1~S4만 공식 입력 자료로 간주합니다. 특히 참가 요금, 환불, 대기 명단에 관한 문장은 원문에 전혀 없습니다. AI가 일반적인 행사 관행을 끌어와 답하지 않도록 이 빈칸도 명시적으로 알려 주는 것이 중요합니다.

입력 자료
S1 행사 일시: 11월 20일 16시
S2 참가: 사전 신청 필수, 정원 16명
S3 준비물: 필기구
S4 온라인 참가: 제공하지 않음

원문에 없는 항목:
- 요금 정보 없음
- 환불 정보 없음
- 대기 명단 정보 없음

source ID는 답변을 멋지게 꾸미기 위한 것이 아니라 검증용 표지입니다. FAQ를 읽는 사람이 S2라는 표기를 보고 원문 S2를 바로 찾아볼 수 있어야 합니다.

02답할 수 있는 질문과 확인이 필요한 질문을 함께 설계하기

FAQ라고 해서 모든 질문에 확정 답변이 있어야 하는 것은 아닙니다. 공지에서 실제로 자주 궁금할 만한 질문을 뽑되, 원문에 정보가 없으면 확인 필요라고 표시하는 것도 정상적인 결과입니다. 이번 실습에서는 정확히 여섯 개 질문을 만들고, 요금과 환불은 하나의 질문에 함께 묶습니다.

요청문
아래 공지에서 FAQ 6개를 작성해 주세요.

규칙:
- 답변은 S1~S4에 실제로 있는 내용만 사용하세요.
- 근거가 있으면 답변 끝에 source ID를 표시하세요.
- 근거가 없으면 내용을 추측하지 말고 확인 필요라고 표시하세요.
- 요금, 환불, 대기 명단은 원문에 정보가 없다는 점을 유지하세요.
- 온라인 참가 제공하지 않음을 가능하다고 바꾸지 마세요.
- 날짜, 시각, 정원 숫자를 변경하지 마세요.

FAQ 질문은 다음 6개로 해 주세요.
1. 행사는 언제 열리나요?
2. 사전 신청이 필요한가요? 정원은 몇 명인가요?
3. 무엇을 준비해야 하나요?
4. 온라인으로 참가할 수 있나요?
5. 참가비와 환불 규정은 어떻게 되나요?
6. 정원이 차면 대기 신청을 할 수 있나요?

이 프롬프트에서는 질문 자체를 고정했기 때문에 AI가 임의로 질문 수를 늘리거나 중요 사실을 빼는 일을 줄일 수 있습니다. 답을 모르겠다는 표시 역시 실패가 아니라 원문 범위를 지킨 결과입니다.

03FAQ 결과 예시를 원문과 대조하기

아래 표는 특정 AI 서비스의 실제 출력이나 성능 측정값이 아닙니다. 입력 자료와 답변의 대응 관계를 설명하기 위해 AI 보조로 구성·검토한 편집 예시입니다. 실제 사용에서는 각 답변의 source ID를 다시 눌러 보듯 원문과 직접 대조해야 합니다.

예시 결과
Q1. 행사는 언제 열리나요?
A. 11월 20일 16시에 열립니다. 근거: S1

Q2. 사전 신청이 필요한가요? 정원은 몇 명인가요?
A. 사전 신청이 필수이며 정원은 16명입니다. 근거: S2

Q3. 무엇을 준비해야 하나요?
A. 필기구를 준비하면 됩니다. 근거: S3

Q4. 온라인으로 참가할 수 있나요?
A. 온라인 참가는 제공하지 않습니다. 근거: S4

Q5. 참가비와 환불 규정은 어떻게 되나요?
A. 원문에 요금과 환불 정보가 없습니다. 확인 필요.

Q6. 정원이 차면 대기 신청을 할 수 있나요?
A. 원문에 대기 명단 또는 대기 신청 정보가 없습니다. 확인 필요.

04그럴듯하지만 원문에 없는 FAQ 답변 걸러내기

FAQ 자동 작성에서 가장 조심할 부분은 일반적으로 있을 법한 규칙을 원문 사실처럼 쓰는 것입니다. 무료 행사, 환불 불가, 대기 접수 같은 표현은 현실에서 흔할 수 있지만 이 가상 공지에는 없습니다. 그럴듯함과 근거 있음은 같은 뜻이 아닙니다.

잘못된 결과
Q. 참가비와 환불 규정은 어떻게 되나요?
A. 참가비는 무료이며 별도의 환불 절차가 없습니다.

Q. 정원이 차면 대기 신청을 할 수 있나요?
A. 네. 16명이 마감되면 자동으로 대기 명단에 등록됩니다.
잘못 추가된 내용원문 상태올바른 처리
참가비 무료요금 정보 없음확인 필요
별도 환불 절차 없음환불 정보 없음확인 필요
자동 대기 등록대기 명단 정보 없음확인 필요

수정할 때는 답을 더 자연스럽게 만드는 것보다 출처 없는 내용을 제거하는 것이 우선입니다. 확인 필요라는 표현 뒤에 문의처를 쓰고 싶더라도 문의처가 원문에 없다면 임의의 전화번호나 이메일을 만들면 안 됩니다.

05출처 없는 답변만 다시 고치게 요청하기

잘못된 FAQ가 발견되면 어떤 문장이 근거 밖인지 구체적으로 지정합니다. 이때 새 정보를 채워 넣어 달라고 하지 않고, 원문에 없음을 명확히 표시하도록 요청해야 합니다. source ID가 없는 답변은 다시 확인 대상으로 삼습니다.

요청문
앞선 FAQ에서 Q5와 Q6만 수정해 주세요.

Q5의 참가비 무료와 환불 절차 없음은 원문에 없습니다. 요금과 환불 모두 확인 필요로 수정하세요.
Q6의 자동 대기 등록도 원문에 없습니다. 대기 신청 가능 여부는 확인 필요로 수정하세요.
S1~S4에 없는 연락처, 정책, 예외 조건을 새로 만들지 마세요.
Q1~Q4의 날짜, 시각, 16명, 필기구, 온라인 참가 제공하지 않음은 변경하지 마세요.

이런 재요청은 원문의 범위를 다시 잠그는 역할을 합니다. 단, 재요청 후에도 Q1~Q4가 우연히 바뀌지 않았는지 최종 확인이 필요합니다.

06FAQ를 공개하기 전에 source ID 중심으로 확인하기

FAQ는 읽기 쉬워야 하지만, 원문보다 정보가 많아져서는 안 됩니다. 질문을 자연스럽게 바꾸는 것은 가능해도 날짜·정원·부정 조건·미정 사항까지 바꾸면 다른 공지가 됩니다. 아래 항목을 하나씩 확인합니다.

확인 목록
[ ] FAQ가 정확히 6개인가?
[ ] 11월 20일 16시가 S1과 일치하는가?
[ ] 사전 신청 필수와 정원 16명이 S2와 일치하는가?
[ ] 준비물이 필기구로 유지됐는가?
[ ] 온라인 참가 제공하지 않음이라는 부정이 유지됐는가?
[ ] 요금 정보가 없는데 무료 또는 유료라고 단정하지 않았는가?
[ ] 환불 정보가 없는데 임의의 환불 규정을 만들지 않았는가?
[ ] 대기 명단 정보가 없는데 대기 가능 여부를 추측하지 않았는가?
[ ] 근거가 없는 답변은 확인 필요로 표시했는가?

실제 공지에 적용할 때는 출처가 없는 질문을 별도 목록으로 모아 담당자가 확인한 뒤 원문 자체를 보완하는 방식도 사용할 수 있습니다. 다만 이 튜토리얼에서는 실제 기관 정책이나 법적 의무를 판단하지 않으며, 오직 주어진 가상 공지 안에서 사실을 보존하는 연습만 합니다.

직접 확인할 항목

S1~S4로 고정한 가상 행사 공지와 원문에 없는 요금·환불·대기 정보를 대상으로 FAQ 여섯 개의 근거 대응을 사람이 검토한 편집 예시

  • FAQ가 정확히 6개인지 확인
  • S1~S4에 있는 날짜·시각·정원·준비물·온라인 참가 조건이 보존됐는지 확인
  • 요금·환불·대기 정보를 새로 만들지 않았는지 확인
  • 근거가 없는 질문이 확인 필요로 표시됐는지 확인
검증 범위의 한계

결과 예시는 AI 보조로 구성·검토한 교육용 편집 예시이며 실제 AI 제품 실행, 응답 정확도, 특정 서비스의 FAQ 생성 기능을 검증한 결과가 아닙니다.

이 주제의 모든 글 ↗

AI로 문서 두 버전 비교하기: 변경·추가·삭제·동일 항목 구분

같은 행사의 안내문 V1과 V2를 AI에 함께 제공하고, 다섯 가지 비교 항목을 변경·추가·삭제·동일로 나누어 확인하는 실습입니다. 삭제된 문장을 임의로 해석하지 않고 문서에 실제로 적힌 차이만 기록하는 방법을 익힙니다.

AI로 자유서술 의견을 주제별로 묶기: 복수 라벨과 분류 보류 다루기

여섯 개의 짧은 자유서술 의견을 정해진 주제로 분류하고, 한 의견에 두 주제가 있으면 복수 라벨을 허용하는 실습입니다. 라벨 합계가 응답자 수보다 커질 수 있는 이유와 근거 없는 만족도·감정 강도 추론을 피하는 방법도 함께 확인합니다.

AI로 어려운 이용안내를 쉬운 말로 고치기: 조건·예외·부정·기한 보존

가상의 자료 대여 안내 네 문장을 쉬운 표현으로 바꾸면서 등록회원 조건, 7일 기한, 예약자료 연장 불가, 비예약자료의 1회 연장 요청 가능과 승인 미확정이라는 핵심 조건을 잃지 않는 방법을 연습합니다.

AI로 조사 질문과 검색 계획 만들기

막연한 조사 목표를 사실 질문, 경험 질문, 결정 질문으로 나누고 무엇을 어디서 확인해야 하는지 검색 계획을 만드는 실습입니다. AI에게 검색 결과를 지어내게 하지 않고, 확인해야 할 자료와 미확인 항목을 먼저 구조화합니다.

AI로 이용자 조사 인터뷰 질문 만들기

가상 신청서 이용 경험을 조사하기 위한 15분 인터뷰 질문을 AI와 설계하는 실습입니다. 유도질문을 최근 실제 행동에 대한 중립 질문으로 고치고, 아직 실시하지 않은 인터뷰의 예상 답변을 실제 증거처럼 쓰지 않는 방법을 다룹니다.

제약조건을 정해 AI로 아이디어 발상하기

참가 인원, 시간, 인쇄물, 구매 가능 여부, 사용 장비처럼 제약조건을 먼저 고정한 뒤 AI에게 서로 다른 대안 4개를 발상하게 하는 실습입니다. 어느 아이디어가 가장 좋은지 결정하는 대신 각 대안이 조건을 지키는지 확인하고, 조건이 바뀌었을 때 다시 요청하는 방법을 다룹니다.

AI로 발표 예상 질문과 짧은 답변 준비하기
