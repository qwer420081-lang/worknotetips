Instalar o Claude Code e fazer a primeira execução: perguntar antes de alterar o código

Verificamos o comando de instalação do Claude Code e as condições de conta de acordo com o sistema operacional e iniciamos a primeira sessão em uma pasta fictícia de prática. Em vez de gerar código imediatamente, fazemos apenas três perguntas para ler a pasta e o CSV no modo plan e depois encerramos a sessão com segurança.

Para quem éUsuários de Windows, macOS, Linux ou WSL que estão instalando o Claude Code pela primeira vez e querem praticar leitura e perguntas antes de modificar arquivos

Preparação
  • Conseguir abrir um terminal ou PowerShell
  • Preparar uma conta compatível ou uma forma de pagamento que possa ser usada com Claude Code
  • Usar o expenses.csv fictício em vez de dados pessoais reais
  • Usuários de Windows nativo devem verificar a recomendação de instalar Git for Windows

01Verificar a conta e o escopo da prática antes da instalação

O Claude Code não deve ser explicado supondo que seu uso seja gratuito. A documentação oficial usada como referência para este artigo apresenta como caminhos de conta uma assinatura Claude Pro, Max, Team ou Enterprise, créditos pré-pagos de API no Claude Console ou um provedor de nuvem compatível. Antes de instalar, verifique na documentação oficial e na tela real da conta qual dessas opções se aplica. Este artigo não inventa preços nem números de versão específicos.

Item de preparaçãoO que verificarEscolha neste artigo
ContaO caminho aplicável entre assinatura Claude compatível, Console ou provedor de nuvemNão presumir que seja gratuito
Pasta de práticaSeparada da pasta de trabalho realUsar vibe-expenses
DadosArquivo fictício sem dados pessoaisUsar expenses.csv
PermissõesNo início, priorizar leitura e planejamento em vez de modificaçãoRecomenda-se o modo plan

No Windows nativo, recomenda-se instalar Git for Windows. Se ele não estiver instalado, o Claude Code pode usar PowerShell como ferramenta de shell. O uso do Git será abordado no artigo 6, então aqui nos concentramos apenas no ambiente de instalação e na primeira sessão.

02Usar o comando oficial de instalação correspondente ao sistema operacional

O comando recomendado de instalação nativa varia conforme o sistema operacional. Antes de copiar os comandos abaixo, verifique qual shell e qual sistema operacional você usa. A documentação oficial informa que a instalação nativa usa atualizações automáticas em segundo plano, enquanto as instalações via Homebrew e WinGet não são atualizadas automaticamente.

Prompt
# macOS · Linux · WSL
curl -fsSL https://claude.ai/install.sh | bash
Prompt
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
Prompt
Windows CMD:
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Homebrew:
brew install --cask claude-code

WinGet:
winget install Anthropic.ClaudeCode

É melhor usar os comandos de instalação exatamente como aparecem na documentação oficial e não misturá-los com scripts modificados arbitrariamente encontrados na internet. Antes de executar, verifique novamente na documentação oficial se os requisitos atuais ou os ambientes compatíveis de cada método de instalação mudaram.

03Verificar a versão sem definir um número específico como valor esperado

Depois da instalação, abra um novo terminal e verifique com `claude --version`. Segundo a documentação oficial, são exibidos o número da versão e “(Claude Code)”. Como o número da versão pode mudar com o tempo, este artigo não fixa um número específico.

Prompt
claude --version

Se aparecer uma mensagem dizendo que o comando não foi encontrado, em vez de adivinhar um caminho, revise novamente a etapa de instalação e a orientação de solução de problemas da documentação oficial. Como este texto não executou o Claude Code de fato, não afirma ter reproduzido uma tela específica de erro ou sucesso.

04Criar uma pasta de prática separada em vez de usar um projeto real

É mais seguro não fazer a primeira execução diretamente em uma pasta de pesquisa ou em um repositório de trabalho, mas criar uma pasta de prática vazia. Aqui usamos apenas uma pasta chamada vibe-expenses e o expenses.csv fictício. Depois de criar a pasta, salve o conteúdo CSV definido no artigo anterior.

mkdir vibe-expenses
cd vibe-expenses

Salve o arquivo em UTF-8. Nesta etapa, não criamos summarize.py. O objetivo da primeira sessão não é “fazer a IA programar imediatamente”, mas praticar a leitura e a explicação da pasta atual antes de o usuário decidir o que será alterado.

05Começar no modo plan e fazer o primeiro login

O Claude Code pode ser iniciado com `claude` dentro da pasta do projeto e, na primeira execução, pode abrir o login no navegador. Para iniciantes, porém, recomendamos começar no modo plan em vez de iniciar diretamente em um fluxo que permita modificar arquivos. O modo plan é um modo de permissões voltado à leitura para revisar análises e planos e pode ser iniciado pela linha de comando da seguinte forma.

Prompt
claude --permission-mode plan

Na primeira execução, pode aparecer o processo de login pelo navegador. Se precisar trocar de conta, você pode usar `/login` dentro da sessão. O modo de permissões padrão pode variar conforme a conta e o ambiente, por isso este artigo não afirma que “é sempre Manual”. Segundo a documentação oficial consultada em 2026-09-22, o modo inicial padrão do terminal interativo nos planos Pro, Max e Team é auto, enquanto nos outros planos é Manual.

06Fazer três perguntas somente de leitura antes de alterar arquivos

Quando a sessão começar, não peça imediatamente “crie o programa”. Primeiro, verifique até que ponto a ferramenta entende corretamente a pasta atual. O Claude Code pode ler sozinho os arquivos de que precisa e pode solicitar aprovação antes de modificar arquivos ou executar comandos. Nesta prática, não pedimos nenhuma modificação; fazemos apenas perguntas.

Prompt
Diga quais arquivos existem nesta pasta. Não modifique nenhum arquivo.

Explique os nomes das colunas de expenses.csv e o que cada uma parece significar. Não modifique nenhum arquivo.

Se você fosse criar uma ferramenta para calcular o total mensal de amount com este CSV, resuma em três pontos o que deveria ser verificado antes da implementação. Ainda não escreva código.

Na resposta, verifique pelo menos se o nome do arquivo atual e as colunas do CSV não foram interpretados incorretamente. Se a IA mencionar um arquivo que não existe ou sugerir uma modificação ou instalação não solicitada, pergunte primeiro o motivo. Como a redação da resposta real do Claude Code pode variar conforme o modelo e o momento, este artigo não inventa um diálogo correto para apresentá-lo como saída real.

PerguntaPonto principal a verificarSe houver problema

Quais são as colunas do CSV?Lê corretamente date, category, amountSe adivinhar nomes de colunas, comparar com o original
O que verificar antes de implementar?Confirma primeiro entrada, saída e restriçõesSe tentar modificar logo, pedir apenas o plano

07Encerrar e seguir para o próximo artigo

Se o objetivo da primeira sessão foi alcançado, encerre sem criar código. Na sessão, você pode usar `/exit` e também encerrar pressionando Ctrl+D duas vezes. `/help` mostra a lista de comandos; há também comandos como `/clear`, `/resume`, `/compact` e `/rewind`, mas neste artigo apenas confirmamos os nomes das funções e não ampliamos o trabalho.

O que é vibe coding? O que a pessoa deve fazer ao delegar código à IA

Entendemos vibe coding não como “pedir em palavras e deixar a IA fazer tudo sozinha”, mas como uma forma de trabalho em que a pessoa define os requisitos e os critérios de verificação e depois revisa o resultado gerado pela IA. Usando como exemplo uma ferramenta fictícia para somar um CSV de despesas domésticas, organizamos em uma única nota a entrada, a saída, o que não deve ser feito e como verificar o resultado.

Criar a primeira ferramenta com Claude Code: total mensal de um CSV de despesas

A solicitação inclui um exemplo de entrada, a saída esperada e as restrições e, depois, executamos o summarize.py concluído na ferramenta Python do chat GPT, e não no Claude Code, para verificar o resultado.

Explicar as regras do projeto com CLAUDE.md

Organizamos de forma concisa no CLAUDE.md do projeto o comando de execução, as regras de dados, as proibições e a forma de verificar resultados que antes eram repetidos em cada solicitação. Distinguimos a função de `/init` para criar um rascunho e o propósito de cada localização de arquivo e concluímos um arquivo de regras de 35 linhas adaptado ao exemplo do CSV de despesas.

Claude Code: planeje antes de editar e amplie funções com o modo plan

Usando como exemplo a adição da opção `--by-category` a uma ferramenta já funcional que soma despesas por mês, você aprenderá a revisar primeiro o plano de mudanças no modo plan do Claude Code. Antes de implementar, definirá o escopo da alteração e o formato de saída; depois de aprovar o plano, executará o código final para verificar tanto os totais mensais existentes quanto os totais por categoria.

Revisar com git o que a IA mudou: do commit inicial ao diff e ao commit final

Você aprenderá um fluxo mínimo para criar um ponto de referência com git antes de o Claude Code modificar arquivos e, depois do trabalho, revisar as mudanças reais com `git status` e `git diff`. É possível pedir à IA que explique o diff, mas o processo se baseia em a pessoa conferir o diff e os resultados da execução antes de fazer staging e commit diretamente.

Corrigir erros com o Claude Code: reproduzir → causa → mudança mínima → executar novamente

Em vez de apenas dizer à IA que “está dando erro”, você praticará um fluxo em que primeiro reproduz o problema com a mesma entrada, restringe a causa com base na mensagem real de exceção e solicita somente a mudança mínima. Usaremos um CSV cujo amount contém uma vírgula para reproduzir um ValueError no Python e executaremos novamente o código corrigido para verificar o resultado.
